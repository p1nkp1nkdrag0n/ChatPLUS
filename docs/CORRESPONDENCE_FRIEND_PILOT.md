# 书信与关系纪念物朋友试用协议

> 状态：待执行的试用协议与记录模板。本文不表示任何朋友试用已经开始或完成。

本协议把实施计划 §12.4 的小样本朋友试用转成可重复执行、可审计的清单。它用于发现跨日、停机恢复、隐私和叙事体验问题，不用于宣称统计显著性。

## 1. 每位试用者的最低完成条件

每位朋友使用一个完全独立的实例，并至少完成三次完整往返。一次完整往返指：用户写信并封缄 → 角色在逻辑抵达时读信并生成回信 → 回信返程并抵达 → 用户启封。

- [ ] 独立 SQLite 数据库，未与其他朋友复用。
- [ ] 独立资产目录，未与其他朋友复用。
- [ ] 独立 `INSTANCE_SECRET`，为至少 32 字节随机值的规范 Base64；未复制其他实例的 `.env`。
- [ ] 本次完整试用显式设置 `CORRESPONDENCE_MODE=enforced` 与 `KEEPSAKE_MODE=enforced`；没有把示例文件的安全默认 `off` 误当成已启用。
- [ ] 试用者知道这是小规模产品试用，知道等待时间、记录内容和退出方式。
- [ ] 提醒试用者不要在测试信中放入不愿保存在其自托管实例里的高度敏感信息。
- [ ] 为本次试用分配不含真实姓名的 `pilot_id` 和 `instance_id`。
- [ ] 试用前运行 `pnpm test:correspondence:focused`，结果通过。
- [ ] 在 API 端口 3001 可用后运行 `pnpm test:correspondence:e2e`，结果通过。

## 2. 三次往返场景

三个场景都必须执行。允许同一封信同时满足“生活事件”和“纪念物”条件，但仍须完成至少三次独立往返。

### 往返 A：服务停机补算

- [ ] 记录用户信件 ID、线程 ID、封缄时间和预计抵达时间。
- [ ] 封缄后停止服务，停机跨过用户信件的逻辑抵达时刻。
- [ ] 在回信逻辑返程已经开始或已经到达后再启动服务。
- [ ] 验证只生成一封回信，没有重复 generation run/commit。
- [ ] 验证 `effective_author_time`、`arrival_due_at`、`processed_at` 和用户实际发现时间含义可区分。
- [ ] 抵达前检查普通详情接口、页面和开发者诊断，确认没有回信正文、密文材料、claim token 或 prompt 泄漏。
- [ ] 启封后重新启动服务并重复访问，确认状态和正文稳定。

### 往返 B：等待期间的角色生活事件

- [ ] 封缄后、角色逻辑收信前，至少发生一条可审计的角色生活事件。
- [ ] 记录生活事件 ID、有效时间和处理时间。
- [ ] 逻辑收信后再产生一条明显不同的事件或事实更正。
- [ ] 验证回信只使用抵达快照截止前允许使用的证据。
- [ ] 验证抵达后的事件或更正没有倒灌进旧回信。
- [ ] 在回信在途时继续一次聊天；角色可以知道“回信已寄出”，但聊天、网络响应和日志均不得出现回信正文。

### 往返 C：纪念物与分享

- [ ] 使用已发生、可追溯的信件/里程碑/结果触发一件纪念物。
- [ ] 记录纪念物 ID、生成任务 ID、资产 ID 和全部来源 ID。
- [ ] 从纪念物详情逐一返回来源，确认链接可用且归属当前实例。
- [ ] 重复触发相同语义来源，确认不会生成重复纪念物或重复主资产。
- [ ] 打开分享编排器，保持“正文摘录”关闭并生成安全预览。
- [ ] 验证默认分享只含明确选择的信封、邮戳、等待天数和纪念物，不含正文、公开 URL 或上传目标。
- [ ] 如测试手动摘录，只选用户自己的信或已经启封的回信；验证摘录确实来自正文，且姓名/地点涂黑范围合法。

## 4. 五项主观反馈

每次往返结束后都询问以下五项，不只在试用末尾问一次。先让试用者用自己的话回答，再记录 1–5 分；`1` 表示强烈负面，`5` 表示强烈正面。

| 主观问题                                             | 分数（1–5） | 试用者原意摘要 | 观察者备注 |
| ---------------------------------------------------- | ----------- | -------------- | ---------- |
| 等待产生了期待，还是只像人为阻塞？                   | 待填        | 待填           | 待填       |
| 回信像“抵达时的角色”写成，还是像延迟发送的聊天回复？ | 待填        | 待填           | 待填       |
| 等待期间的生活变化是否自然、相关且不过度抢戏？       | 待填        | 待填           | 待填       |
| 纪念物是否能说清来历，还是像随机 AI 图片？           | 待填        | 待填           | 待填       |
| 是否愿意重开旧信，或把信封/物件分享给朋友？为什么？  | 待填        | 待填           | 待填       |

附加行为记录：

- [ ] 已到达回信是否在下一次访问时启封：是 / 否 / 未到达。
- [ ] 首封回信后是否主动寄出第二封：是 / 否。
- [ ] 试用者能否准确解释“写于 / 寄于 / 到达 / 发现”：完全 / 部分 / 不能。
- [ ] 一周后是否再次打开旧信或档案：是 / 否 / 尚未回访。

## 5. 技术、隐私与安全事件记录

任何异常都单独建一条记录；“没有事件”也必须显式勾选，不能留空。

- [ ] 本次往返未发现技术、隐私或安全事件。
- [ ] 本次往返发现事件，已按下面模板登记并关联到匿名 `pilot_id`。

```text
incident_id:

severity: blocker | high | medium | low
category: duplicate_reply | future_fact_leak | plaintext_leak | key_mismatch |
          cross_instance_data | bad_timestamp | state_regression |
          broken_provenance | asset_integrity | unexpected_cost | other
affected entity IDs (no content):
expected behavior:
observed behavior (redacted):
reproduction steps (redacted):
was plaintext exposed outside the authorized open response?: yes | no | unknown
was another instance affected?: yes | no | unknown
containment taken:

```

遇到以下任一情况应立即暂停受影响实例的试用，不继续“看看会不会再发生”：跨实例数据、未启封正文泄漏、密钥/指纹异常、重复回信提交、未来事实进入旧快照、资产哈希不一致。

## 6. 单人试用完成检查

- [ ] 至少三次完整往返均有事实记录和五项主观反馈。
- [ ] 至少一次覆盖服务停机补算。
- [ ] 至少一次覆盖等待期间角色生活事件与快照截止。
- [ ] 至少一次生成可追溯纪念物并验证默认无正文分享。
- [ ] 重复回信为 0。
- [ ] 未来信息泄漏为 0。
- [ ] 未授权正文泄漏为 0。
- [ ] 所有状态转换和关键来源都能追溯到实体 ID 或 domain event ID。
- [ ] 技术/隐私事件已显式记录为“无”，或已有事件单和处理状态。
- [ ] 已安排一周后的旧信/档案回访问题。

完成这些检查只代表该朋友的协议执行完毕，不自动代表产品达到发布门槛。汇总时应同时报告样本数、未完成项、失败场景和事件，而不是只报告平均评分。
