# Dearvale 好友联网测试版

这一入口运行独立的托管实例。账号、邀请码、模型配置、积分账本及研究记录放在新的服务数据目录；每个账号的角色、消息、书信、记忆和成就使用自己的 SQLite 和资产目录。现有单机启动命令与安装包继续可用。

## 启动与首次配置

要求 Windows、Node.js 22–24、项目指定的 pnpm，以及已安装的工作区依赖。在项目根目录运行：

```powershell
pnpm install --frozen-lockfile
pnpm hosted:serve
```

`hosted:serve` 构建网页并启动服务。之后网页代码未变时可直接用 `pnpm hosted:start`。进程需要持续运行；电脑睡眠、关机或关闭服务进程时，好友无法访问。重新启动后，服务会打开已激活账号的运行环境并恢复后台调度。

停止或升级前执行 `pnpm hosted:stop`。它通过受限数据目录内的本机控制文件请求服务暂停接纳新操作，等待在途请求和后台任务结束，再关闭数据库；没有新增网络管理端点。使用自定义目录时，停止命令与启动命令必须使用相同的 `DEARVALE_HOSTED_ROOT` 或 `DEARVALE_HOSTED_CONFIG`。命令超时会报错，不会强制结束进程。

首次启动默认：

| 项目       | 默认值                        |
| ---------- | ----------------------------- |
| 数据目录   | `%APPDATA%\DearvaleServer`    |
| 用户监听   | `127.0.0.1:3001`              |
| 管理监听   | `127.0.0.1:3002`              |
| 管理网页   | `http://127.0.0.1:3002/admin` |
| 本机预览   | `http://127.0.0.1:3001`       |
| 新付费调用 | 暂停，配置完成后由管理员开启  |

服务不会读取项目原有 `.env`。需要改变数据目录、端口或公网地址时，把根目录 `.env.hosted.example` 复制到你管理的私人目录，编辑它，然后指定绝对路径：

```powershell
$env:DEARVALE_HOSTED_CONFIG = 'C:\DearvaleConfig\hosted.env'
pnpm hosted:serve
```

配置项包括 `DEARVALE_HOSTED_ROOT`、`DEARVALE_HOSTED_PORT`、`DEARVALE_ADMIN_PORT`、`DEARVALE_PUBLIC_ORIGIN`；可通过 `DEARVALE_WEB_DIST` 指定构建好的网页目录。后台供应商凭据不放在该配置文件中。托管实例默认启用常驻书信功能；可显式设置 `CORRESPONDENCE_MODE=off` 关闭。额外的关系纪念物生成功能保留原有开关，徽章生图由托管模型映射单独管理。

打开本机管理网页，创建第一个管理员。后台依次完成：

1. **模型与价格：** 添加稳定的公开 ID、显示名称、供应商协议、HTTPS API 地址、真实模型 ID 和 API Key；填写积分价格、最大输出和上下文上限。保存后的凭据不回显。
2. **用途映射：** 设置文本默认模型；需要时分别指定角色编译、对话、回复修复、记忆、书信等用途。徽章生图使用 `achievement_badge`，必须指定图片模型。
3. **维护与限制：** 核对账号每日限额、全站每日限额、队列和并发。确认价格及预算之后开启付费调用。
4. **邀请码：** 发放邀请码并填写初始积分。默认单次、七天有效、初始零积分；可增加使用次数、指定有效期或停用。
5. 使用独立的测试账号完成一次小额调用，核对供应商控制台和 Dearvale 账单，然后邀请其他好友。

文本模型的输入、输出积分价格必须大于 0，缓存命中可以为 0，缓存写入可留空以采用输入价；图片每张价格必须大于 0。未完成价格配置的模型保存为停用草稿。启用调用总开关时会检查启用模型的价格和凭据，实际发送请求前也会再次检查；零价不能绕过余额保护。历史请求继续使用当时的快照，已经保存的回复可恢复而不会重新收费。

管理员可搜索用户名或参与者编号、调整积分、封禁和解封、重置密码。重置密码会撤销该账号的旧会话并要求重新设置密码。封禁会撤销登录、关闭事件连接、取消排队、阻止新调用并尽力中止已发出的调用；已经确认的消耗仍然结算。

## 公网入口与联网安装包

服务不依赖特定穿透平台。配置固定的 `https://...` 公网源站地址后，将穿透的目标设为 `127.0.0.1:3001`，**仅转发用户端口**。保留浏览器原始公网 `Host`；不要让代理把它改成 `127.0.0.1:3001`。服务会严格检查 Host、Origin、会话 Cookie 与 CSRF。

管理服务独立绑定回环地址，其管理路由没有注册到用户监听器。无需对外开放 3002、数据库或资产目录。代理应支持 SSE、关闭事件缓冲、允许至少 240 秒的长请求，并允许 500 KB 的文本上传。公网地址不匹配会返回 421；使用 HTTP 或错误 Origin 的写入会被拒绝。

### Sakura Frp（Windows）

仓库提供 `scripts/hosted-sakura.ps1` 管理一个 Sakura 隧道。它独立于 Dearvale 服务运行，不需要管理员权限；先启动 Dearvale，再启动隧道。脚本默认读取 `%LOCALAPPDATA%\DearvaleTunnel\sakura.json`，可用 `-Root` 指定另一个私人目录。该目录应限制为当前 Windows 账户、SYSTEM 和本机管理员访问；脚本会拒绝过宽的文件权限或符号链接等重解析路径。

首次使用前，先在 Sakura 控制台配置一个指向 **`127.0.0.1:3001`** 的用户隧道，并准备以下文件：

| 相对隧道目录的路径            | 内容                                                                                          |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `sakura.json`                 | 非秘密配置，必填数字字符串 `tunnelId`；可选 `binarySha256` 用于固定已独立核验的新客户端版本。 |
| `bin\frpc_windows_amd64.exe`  | 从 Sakura 官方下载入口取得并完成校验的 Windows amd64 客户端。                                 |
| `.secrets\sakura-token.dpapi` | 由运行脚本的同一 Windows 账户生成的 DPAPI 加密访问令牌。                                      |

脚本不自动下载客户端，也不交互创建令牌。下载时，应通过 Sakura 官方 HTTPS 页面获取客户端及该版本公布的 MD5，逐项核对文件、平台、版本和 MD5；不要使用来源不明的镜像或第三方提供的校验值。MD5 用于核对官方发布文件，不能单独证明来源可信。完成下载核验后另算 SHA-256 并固定版本；脚本启动前校验 SHA-256，默认固定已核验的 `sakura-14` Windows amd64 文件。更新客户端时须重新核验，再更新 `binarySha256`，不能为跳过校验而直接接受任意新文件的哈希。

令牌文件使用 Windows `ProtectedData.Protect`、`CurrentUser` 范围，明文为令牌的 UTF-8 字节，附加熵为 UTF-8 字符串 `DearvaleTunnel:SakuraToken:v1`。应在受限目录中通过不回显的安全输入流程预先生成该文件。不要把令牌写入 PowerShell 命令、命令历史、转录日志、`sakura.json`、`frpc.ini` 或项目文件；换 Windows 账户或电脑时需要重新配置凭据。运行时，脚本只在 `frpc` 子进程环境中设置 `NATFRP_TOKEN` 和 `NATFRP_TARGET`，命令行不含令牌，也不生成含令牌的明文配置。子进程仍需要在内存中持有凭据，因此 DPAPI 不防御以同一 Windows 账户运行的恶意程序。

在项目根目录使用 Windows PowerShell 5.1 或更高版本运行：

```powershell
powershell.exe -NoProfile -File .\scripts\hosted-sakura.ps1 start
powershell.exe -NoProfile -File .\scripts\hosted-sakura.ps1 status
powershell.exe -NoProfile -File .\scripts\hosted-sakura.ps1 stop
```

自定义目录时，三个操作都添加相同的 `-Root 'C:\DearvaleTunnel'`。`start` 在后台启动受管进程；返回 `running` 只表示进程已经启动，不能代替公网验收。`status` 返回 JSON 状态及最近事件，例如 `node_authenticated`、`tunnel_online`、`authentication_error`、`connection_error` 或 `local_service_error`。固定事件记录保存在隧道目录的 `logs\sakura-events.jsonl`，不会保存 `frpc` 的原始输出。`stop` 只停止这一次受管隧道，不停止 Dearvale，也不按进程名称批量终止其他隧道；停止超时或出现 `orphaned_agent` 时，应先检查状态和对应实例，避免反复启动。

Sakura 公网入口必须提供有效证书的 HTTPS，并保留完整公网 `Host`，包括非标准端口。例如公网入口为 `https://friends.example.com:44321` 时，`DEARVALE_PUBLIC_ORIGIN` 和联网客户端均填写该完整地址，转发的 `Host` 应为 `friends.example.com:44321`；不要省略端口，也不要改写为本机地址。修改 `DEARVALE_PUBLIC_ORIGIN` 后重启 Dearvale。用户浏览器到公网入口使用 HTTPS；隧道转发到本机的 HTTP 回环监听是内部一段连接。保持登录 Cookie 的 `Secure` 属性，不要通过关闭它或放宽 Host、Origin、CSRF 检查来绕过代理配置错误。**不要建立指向管理端口 `127.0.0.1:3002` 的隧道，也不要让隧道根目录成为静态资源目录。**

隧道进程上线后，仍需从朋友实际使用的外部网络完成以下验收；本节不代表这些公网检查已经通过：

1. 检查 HTTPS 证书及含端口的完整地址，确认用户页可达，管理 API 无法从用户入口访问；分别验证错误 Host、错误 Origin 和无效会话会被拒绝。
2. 完成注册、登录、刷新、退出和重新登录，检查会话与 CSRF 正常工作。退出后再重连网络或重新打开页面，应要求重新登录；旧 Cookie 和旧事件连接不能继续读取该账号数据。
3. 验证 SSE 能持续接收事件，网络短暂断开后能恢复连接，退出登录后停止自动重连；封禁或重置密码后，原会话不能恢复事件订阅。确认代理没有事件缓冲或过短的空闲超时。
4. 先用不调用付费供应商的读取操作验证连接与上传规则。完成价格和限额配置后，再用一次受控小额生成验证至少 240 秒长请求、界面恢复与账本一致性；确认连接中断和重连不会产生重复付费调用。不能仅凭首页能打开就视为生成链路验收通过。

### 联网安装包

独立构建命令：

```powershell
pnpm online:desktop:dist
pnpm online:android:build
```

默认产物：

- `artifacts/desktop-online/Dearvale-Online-0.1.1-Setup.exe`
- `artifacts/android-online/Dearvale-Online-0.1.1.apk`

Windows 应用标识为 `com.dearvale.online`，用户数据目录独立，安装包不包含本地业务服务器。Android 包名为 `app.dearvale.mobile.online`，不包含单机网页资产，也不覆盖单机版。两端在连接页填写同一个 HTTPS 公网地址；服务器地址不编译进安装包。远程页面只能访问服务器同源资源。Windows 远程网页关闭 Node.js 集成、开启隔离与沙箱；Android 使用系统证书校验，拒绝明文 HTTP。

好友在注册页输入用户名、密码和邀请码。新账号登录后先完成模型设置，再进入 Welcome 欢迎页。使用同一账号在另一设备登录即可读取该账号的数据和模型配置。断网时显示连接失败及重试入口。

## 用户首次设置与个人供应商

首次页面显示“我们需要确定一些设置”，提供两个入口：

- **我没有API-KEY**：选择平台文本模型，保存后进入 Welcome。
- **我有API-KEY**：填写供应商 URL、API Key 和协议，检测模型列表并用下拉框选择，也可手填模型 ID；调整参数后保存并执行短回复与结构化测试，通过后进入 Welcome。

首次选择批量初始化全部文本功能。图片生成继续使用平台模型，引导中明确说明会消耗额度。之后可从“设置”进入独立的“模型与功能”页面，为聊天、角色生成、回复复核、记忆、书信、日记等用途分别选择平台模型或自己的模型；支持批量应用到全部文本功能，图片也有单独的平台模型选择器。自带图片供应商当前不在支持范围内。

每个新模型的用户上下文预算默认 64,000 token，可按需修改。检测接口提供的上下文、独立输入和最大输出限制作为单独元数据保存，用于展示与约束实际预算；刷新模型列表保留已配置参数。聊天还受到应用总窗口及输出预留约束，填写更大的值不会提升供应商实际能力。连接测试与参数细节见[模型设置说明](MODEL_SETTINGS.md)。

当前会话明确选择的模型优先于账号的聊天功能设置，其他功能读取各自的绑定。未设置的功能采用平台对应用途模型；用户模型失效、凭据缺失或调用失败时报告错误，不自动退回平台扣费。同一次操作已捕获的模型配置保持稳定，修改用于后续操作。

个人供应商、模型参数、功能绑定和首次设置完成状态均保存到服务端的该用户数据库。URL 与 API Key 使用 AES-256-GCM 分别加密，读取配置不返回 Key；普通模型参数与功能设置不属于加密字段。网页与安卓连接同一服务器、登录同一账号后直接使用这些设置，无需在设备上重新保存 Key。配置版本检查可阻止两端互相覆盖过期编辑。升级前已有账号保留原有配置并迁移为已完成首次设置，不重新展示引导。

供应商请求由服务端发出，结果经业务解析和持久化后通过既有响应与事件机制同步给客户端，不做上游 token 流的原样透传。发现、测试与正式调用共用公网 HTTPS 出站限制：拒绝 URL 内的账号、查询凭据和片段，禁止本机、内网、链路、云元数据及其他特殊地址；逐次校验全部 DNS 结果，将连接绑定到已校验地址并禁止重定向，同时限制体积、超时和取消。手机可达但服务器不可达的接口仍会测试失败。

## 积分与模型规则

**1 积分 = 1,000,000 个整数记账单位。** 后台界面输入积分价格，API 和账本以 `Micros` 整数传输与保存。每个实际平台供应商请求单独冻结、结算；每次费用向上取整到最小记账单位。显示名、真实路由、价格和配置版本记录在该次请求的快照中。

**自带 Key 的文本调用、模型发现与回复测试不冻结、不扣除平台积分**，零积分账号也可使用自己的模型。其调用记录标记为用户凭据来源、平台费用为 0；供应商未返回用量时保留“未知”，不会因此冻结积分。供应商自身可能产生 API 用量费用。用户调用仍受账号状态、全站调用开关、请求大小、并发和队列约束；平台每日积分预算不限制自带 Key 调用。

文本价格单位为“积分 / 百万 token”：

```text
费用 = ((输入总 token − 缓存读取 token − 缓存写入 token) × 普通输入价
       + 缓存读取 token × 缓存读取价
       + 缓存写入 token × 缓存写入价
       + 输出 token × 输出价) / 1,000,000
```

缓存写入价格留空时采用普通输入价。计费使用供应商返回的真实用量，现有业务日志中的估算不参与扣费。未提供的用量显示为未知；若缺少缓存字段但各类输入价格相同，仍可据输入总量结算。价格有差异、用量缺失或计数矛盾时转为待核对。

平台请求开始前，按照受限的输入体积及模型输出上限冻结保守额度。因此余额高于一次实际小回复的费用，也可能不足以承担当前模型的预留上限；可由管理员减小输出上限或增加积分。用户可按功能覆盖服务器用途映射，未设置时仍使用平台映射。使用平台模型的内部调用与真实重试也计入该账号账单；一次操作中，聊天使用自己的模型而复核使用平台模型时，只有平台调用扣分。

图片使用“积分 / 张”，首版每次生成一张徽章。图片模型配置示例规格为 `1024x1024:high`，可使用供应商支持的尺寸和质量；Gemini 当前适配 1024 方图。生成已确认后，后续下载或处理失败不会再次生图；恢复优先使用已保存的供应商结果。配置文本默认模型不能代替徽章图片用途映射。

默认全站并发 4、同账号并发 1、图片并发 1，队列 40；每日默认账号限额 100 积分、全站限额 1,000 积分。限额统计包括已扣费用和仍冻结的额度。邀请码和余额不连接支付，不代表供应商现金余额。

余额不足时可继续阅读已有内容和使用自己的模型。回复下方显示该轮输入、输出、缓存命中、积分和结算状态，展开后查看各用途。角色创建和后台任务等费用在“我的账号”明细中查看。平台模型接口只返回公开名称与计费摘要，不返回平台真实供应商配置；个人供应商设置仅对所属账号开放，研究正文不通过普通用户接口返回。

## 待核对与故障恢复

- 平台调用明确没有发出时释放冻结；已确认用量的失败请求仍扣分。
- 平台请求网络中断、未收到完整用量或进程中断后结果不明时，保留冻结，后台显示待核对。不要用“重新生成”替代核对。自带 Key 请求结果不明时同样阻止不确定的重复发送，但没有平台积分冻结。
- 管理员查询供应商记录后，在“账单与核对”补录实际积分或释放冻结，填写处理依据；处理会写入审计记录。
- 同一客户端请求 ID 对应同一输入。重复提交会返回已保存结果；改变输入却复用 ID 会返回冲突。
- 已结算响应独立持久化。若业务数据库提交失败，原操作保持可恢复；再次提交同一请求会回放已保存响应并补写业务记录。业务已提交但 HTTP 确认丢失也不会重复扣费。
- 研究存储或调用记录不可写时停止新模型请求。全站暂停开关同时阻止平台和个人供应商的新请求，不抹去已产生费用。

## 研究数据、导出与删除

研究库与各账号聊天库分开。记录用户提交、最终显示回复和失败结果；每次供应商请求另存提示、上下文、参数、原始响应、用量、模型与价格快照。图片保存加密研究副本、规格和哈希。删除用户聊天或角色不会删除这些研究记录。

自带 Key 的正式调用、模型发现和回复测试沿用同一研究采集流程；首次设置及个人供应商页面不新增采集许可确认或提醒文案。用户模型调用快照保存用途、模型参数、配置版本和零平台费用来源，不复制明文 URL 或 API Key。

记录以参与者 UUID 关联，在管理界面可关联用户名；导出不附带用户名或密码。参与者编号不是对正文匿名化的保证，正文可能仍含身份信息。当前注册流程不要求同意字段，新账号的同意版本与时间留空；已有同意记录保留，旧客户端提交有效版本并明确同意时仍可记录。研究正文和管理操作不进入普通聊天界面。

可按参与者、会话、操作、时间、真实模型 ID、用途和记录类型检索。列表分页；“导出筛选结果”导出匹配的全部 JSONL 记录。图片记录包含自包含的图片数据及文件名、SHA-256 清单，可用于后续提取验证。管理员可以删除研究记录；删除会清除正文并留下审计和状态信息，之前已经下载的导出或离线备份需另行管理。默认保留天数为 0，表示不自动清理。

需要独立图片文件时运行 `pnpm hosted:extract-research 'D:\Research\export.jsonl' 'D:\Research\new-images'`。目标必须是新的空目录；工具逐张验证哈希，拒绝路径越界，并输出图片与保留参与者、会话、操作关联的 `manifest.json`。

API Key、密码和传输认证头不作为采集字段。账号密码使用 Argon2id；模型凭据、研究正文、恢复响应和图片研究副本使用 AES-256-GCM 认证加密。平台主密钥位于受限的 `.secrets` 目录；个人供应商 URL 与 Key 使用各账号 `users/<用户ID>/business.sqlite.llm-key` 文件中的专用密钥，并分别绑定密文用途与供应商。Windows 服务数据目录的访问控制限定为运行服务的用户和 SYSTEM。

模型出口会在保存研究副本或返回业务层前，精确清除供应商响应中回显的已配置 API Key，包含请求编号、保留的响应头和 JSON 转义形式；密钥轮换时同时保护本次请求的旧凭据和当前凭据。脱敏不改变实际发往供应商的请求，也不删除没有匹配密钥的图片恢复引用或用量字段。

Windows 平台主密钥额外使用当前 Windows 账户的 DPAPI 保护；账号的 `.llm-key` 文件依赖服务数据目录权限保护。旧的 32 字节平台主密钥会在启动时经验证后原子迁移，已有研究密文保持可读；迁移失败保留原文件并停止启动。复制目录到另一台电脑或 Windows 账户时，请使用带独立密钥包的口令加密备份进行恢复。仅拷贝 DPAPI 文件不能代替可移植备份。DPAPI 不防御以同一 Windows 账户执行代码或读取服务进程内存的攻击。

业务聊天、归档、全文检索与书信数据库仍为普通 SQLite，依靠上述文件权限保护；研究副本加密不等于业务全库加密。需要抵御离线读取时，还应为数据磁盘启用系统磁盘加密并另存恢复密钥。

安全事件记录在数据目录 `logs/security-events.jsonl` 中，包含登录相关事件、拒绝请求与管理员写操作的时间、入口、方法、服务端路由模板、状态码和账号编号。它不记录原始 URL、查询参数、正文、认证头、密码或 Key；达到 1 MiB 自动轮换，最多保留 4 个文件。该目录不由 Web 静态服务提供。

## 加密备份与恢复检查

在“维护与限制”输入至少 12 字符的备份口令。服务会暂停接纳新调用、等待在途业务与后台任务结束，再对中央库、研究库、账号业务库和资产进行一致性快照。备份期间两个 API 入口暂停写入。完成或失败后恢复调度。

每次输出两个独立加密文件，使用相同口令：

- `.dvbackup`：业务数据、加密研究数据、资产与清单。
- `.dvkeys`：匹配的平台解密密钥、实例密钥和各账号的 `.llm-key` 文件；恢复个人供应商 URL 与 API Key 同样需要此包。

**将密钥包复制到与日常数据备份不同的安全位置，另行保存口令。** 两包绑定同一个备份编号；缺包、错配、错误口令、路径越界或文件哈希不一致均拒绝恢复。不要提交这些文件或服务数据目录到 Git。

在停止服务后，选择一个新的空目录进行恢复检查：

```powershell
pnpm hosted:restore 'D:\Backups\example.dvbackup' 'E:\PrivateKeys\example.dvkeys' 'C:\DearvaleRestored'
```

交互终端会无回显询问口令；非交互环境可提供 `DEARVALE_BACKUP_PASSPHRASE`。恢复会验证全部文件哈希和 SQLite 完整性，拒绝覆盖非空目录。检查成功后，把 `DEARVALE_HOSTED_ROOT` 改为恢复目录并重新启动服务，再验证登录、角色读取和积分明细。

当前备份实现针对小规模测试，限制原始文件总量为 512 MiB；压缩、JSON/base64 和加密在内存中完成，峰值内存可能明显高于该值。超过上限会明确拒绝，不生成不完整备份。持续采集大量图片后，应在数据达到上限前升级为流式备份。

研究原图单张上限为 32 MiB，图片提取工具单条 JSONL 上限为 64 MiB。设置非零保留天数后会立即清理过期研究正文，服务重启及每小时再次检查；0 表示不自动删除。

## 开发与验收

```powershell
pnpm test:hosted
pnpm typecheck
pnpm --filter @personasim/web build
```

托管测试使用新的临时目录和模拟供应商，不读取开发 `.env`、不迁移单机数据、不消耗真实 API 余额。覆盖中央事务、账号隔离、撤销会话、CSRF、价格快照、缓存计费、并发准入、未知用量、图片下载恢复、研究存储故障、重复请求、聊天写入失败后重启恢复、30 账号驻留及双包备份恢复。个人模型测试还覆盖零积分调用、用途选择、凭据与 URL 加密、诊断采集和持久回复恢复；安全传输使用可控 DNS 与响应验证特殊地址拦截、连接地址绑定、重定向、体积和取消边界。

公网地址与真实模型配置完成后还需在朋友的实际网络中验证 HTTPS 证书、SSE 重连、上传和长请求，并用供应商账单核对各模型返回的缓存及输出口径。这些检查依赖之后选择的穿透平台和真实供应商，模拟验收不能替代它们。
