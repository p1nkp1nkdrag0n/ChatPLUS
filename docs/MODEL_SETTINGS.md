# 模型设置与连接验证

在“设置”的供应商列表点击“添加供应商”，填写名称、接口类型、API 地址和密钥。API 地址为接口根路径，常见示例：

| 接口类型           | API 根地址示例                                     |
| ------------------ | -------------------------------------------------- |
| OpenAI 兼容        | `https://api.openai.com/v1`                        |
| Anthropic Messages | `https://api.anthropic.com/v1`                     |
| Gemini             | `https://generativelanguage.googleapis.com/v1beta` |
| 本地 OpenAI 兼容   | `http://127.0.0.1:11434/v1`                        |

聚合网关可以使用自定义路径。无需鉴权的本地服务允许密钥留空。已有密钥不回显；编辑时留空保留旧值，输入新值替换，勾选“清除已存密钥”才会清除。

点击“检测模型”读取列表，再从下拉框选择模型。若供应商没有列表接口，直接添加模型 ID 也可以使用。列表可搜索，多个模型各自保存高级参数；刷新列表不会覆盖已配置的高级参数。

高级设置默认折叠，包括请求超时、结构化方式、思考设置、输出 token 上限和上下文上限。新模型默认使用提示词 JSON，思考设置使用模型默认值。不同原生协议仅显示对应的参数；检测列表不等于检测模型所有能力。

## 保存、默认与会话选择

“保存配置”保存供应商、凭据和模型参数，不产生生成请求。“全局默认模型”用于跟随默认的会话、角色生成与后台模型任务。已有环境变量配置仍可作为只读来源，使用“复制为可编辑配置”交给页面管理；原 `.env` 不会被修改。

对话输入框上方可以跨供应商切换模型，选择只保存到当前会话，从下一条消息开始使用。选择“跟随全局默认”后，该会话继续跟随全局设置。切换不会改变历史消息或清空正在输入的文字。

每一轮生成及自动修复固定使用开始时捕获的配置，两个会话不会串模型。删除供应商后，引用它的会话会显示失效并要求重新选择；应用不会默默改用另一家供应商。删除全局默认供应商或其默认模型前，请先更换默认选择。

## 如何判断模型可用

“测试连接与回复”针对当前模型最多发送两次真实短请求：先确认能返回非空、可见的简短文字，再要求返回包含非空 `reply` 的 JSON，使用实际生产适配器解析并校验。

- **绿色**：短回复与结构化测试都通过，展示模型实际回复、耗时和时间。
- **橙色**：模型能返回文字，但结构化测试失败；调整该模型的结构化参数后重试。
- **红色**：连接、鉴权、模型访问、正文或响应格式失败，结果框显示具体原因。
- **未验证**：未测试，或 URL、密钥、模型参数已经变化；旧结果不能证明当前配置可用。

模型列表接口不可用不会阻止手填模型的回复测试。HTTP 200 但正文为空、仅有思考、输出截断、拒绝、无效 JSON 都不会显示完全通过。结果只证明本次短请求成功，长上下文和角色业务能力仍需实际使用验证。

测试无自动重试，无聊天兜底，不携带角色资料，也不写入聊天、记忆或角色状态。每项最多等待 120 秒，测试输出上限为模型配置上限与 4096 token 的较小值；不会为通过测试而暗中关闭思考。预算不足会明确报告，可取消等待。保存或切换模型不会自动测试。

## 密钥与备份恢复

页面凭据使用 AES-256-GCM 加密存入数据库，主密钥位于 `${DATABASE_PATH}.llm-key`。例如数据库为 `data/personasim.sqlite`，对应文件为 `data/personasim.sqlite.llm-key`。首次保存非空 API Key 才创建该文件。它与书信的 `INSTANCE_SECRET` 相互独立。

备份格式 v2 包含供应商密文与主密钥指纹，不包含主密钥文件；旧 v1 备份仍可读取。请将 `.llm-key` 单独保管，恢复时显式提供：

```powershell
pnpm selfhost:restore -- --backup <备份目录> --database <新数据库路径> --assets <新资产目录> --llm-key-file <原主密钥路径>
```

恢复会先校验指纹，再将密钥放到目标数据库旁。丢失或不匹配时不会覆盖原密文，也不会阻止读取现有聊天；相关模型凭据会显示不可用。可以恢复原主密钥，或在设置中明确重置供应商凭据后逐一重新填写 API Key。重置保留供应商地址、模型、会话和聊天数据。

仅需恢复聊天数据而没有主密钥时，可在备份/恢复命令显式使用 `--allow-missing-llm-key`；模型凭据恢复范围会单独报告。这不会绕过原有书信 `INSTANCE_SECRET` 校验。
