## 执行规则

每批先明确影响范围，再修改和运行必要回归，审阅 diff 后独立提交。共享模块变更应检验原有正向能力，不能用“全部不记”消除误报。无需迁移的批次不改变持久化契约；涉及旧数据的处理必须可验证、幂等，保留来源与取代链。

离线回归用于复现已定位问题和检查产品路径。模型的自然性、主体连续性、场景覆盖与 README 的双方生活目标仍需逐条审阅新的真实对话；修复后不能把旧的失败实测重新标为通过，也不能把 fixture 成功当成真实模型验收结果。

## 修复中发现的二次耦合

- 发生提取的肯定谓词与否定谓词曾使用两套清单，导致“昨天没有去散步”“没发出邮件”漏过否定过滤。现在共用谓词来源，计划、差点发生、转述和陌生主体都在有效分句内判定；同消息后续明确完成的独立行动仍可保留。
- 选择匹配不再保证返回一个选项。调用方必须处理“未明确”，把没有实际选择的建议/委托回复保留为讨论，不创建决定。旧测试中直接注入的困境需补入真实来源消息，生产实现不为虚构测试来源放宽限制。
- 仅为历史加时间字段不足以正确恢复：书信的首次可见时间必须随首次打开的步骤结果保存。恢复时重建公开历史复用该时间。输入协议因此升级为 v3，旧实验不能接着用新协议改写。
- 证据 ID 正确并不保证自传语义正确。一次真实 GLM 定向验证通过了结构校验，但把角色的话写成用户的话，并补出了无直接依据的“彼此更贴近”。原失败结果保留在 `tmp/checkpoint-fix-live-verification-1788599894006/`，它推动了后续完整原文报告方案。
- 自传正文进入聊天提示词后还会经过两层裁剪。现在两层都只选择完整字段和完整条目，不截断原话末尾的否定、条件或归因。超出预算的内容省略，持久化原文不变；这项投影修复同时兼容旧快照。
- 长消息索引还需兼容角色故事时钟：主机 UTC 时间保留在可投影的证据字段，不拼进正文。1951 年角色的提示词会得到对应故事日期，档案仍保留原始 2026 年记录时间；相关 52 项回归通过。
- 同一条消息可以同时谈散步和外包，不能先给整条消息选一个决定，再把所有行动和结果挂上去。现在按有效分句、主体和阶段分别关联；历史记录也只投影出同事项的实际证据，避免旧的混合摘要继续传播错误关联。
- 共享 FakeClock 的用户消息和角色回复可能时间完全相同，仍有发言顺序。用户先报告的行动或结果不能关联角色随后才作出的决定，也不能把随后才出现的角色行动当成先前结果的原因；跨轮真实后续仍保留。
- 外部拒绝是结果，不能把“申请被拒绝”拆成自己又申请了一次。反思没有唯一对应结果时可以保留对决定的反思，但不默认连接最近结果。小型有限选择的记录继续保留，显著性和标题不再把每次散步都描述成人生转折。

因果回归中同步修正了原先不成立的测试前提：泛泛说“改变现状”或选择范围之外的“继续画画”不能算明确选择；承认愿意承担创作的不确定性可以是反思，但未必指向某一次具体经济后果。相关正例补充了真实公开来源或明确选项，没有通过放宽生产校验恢复旧断言。

最终顺序回归还揭示一个旧测试的伪通过：首句“授权你在留下和正式辞职之间作决定”被当作实际行动，而下一轮真正“向主管提出离职”没有关联。前者需要排除授权中的候选行动，后者需要在有效发生分句内复用已验证的选项别名匹配。测试因此核对逐轮行动数量及来源消息，而不是只断言最终存在一条行动。

全库第一次回归另出现 `companion-long-run-v2-runner` 的 `fetch failed / bad port`：操作系统分配的本地监听端口可能被 Fetch 的端口限制拒绝。已在同一个本地 10080 端口验证 Fetch 拒绝、Node HTTP 可正常返回；探针结束关闭了监听。修复只替换长测内部 loopback 客户端为 `node:http`，保留真实 HTTP、请求/响应内容、状态与延迟，模型请求仍经原 fetch 和 observer。确定性回归模拟 fetch 拒绝，验证中文消息、来源观察及重启；不采用循环重试掩盖失败。
