# 角色问答创建流程与交互规范

## 已实现的流程

Welcome 从服务端读取已发布的用户角色，决定显示「描述你梦中的他/她」或「继续聊天」。未完成的问答和未确认小传可恢复；服务器读取失败提供重试，离线暂停不按空库处理。导入后发布的角色也启用聊天。最后一个角色归档后恢复创建邀请。

服务器启动不再播种系统示例，旧 SEED_DEMO 配置也不启用播种。公开的示例创建接口返回 410。033 迁移只归档来源或示例注册记录明确识别的角色，保留角色和会话数据，不按角色姓名识别。

`/create` 使用独立书桌场景，按固定顺序呈现十二题。性别、姓名、文字年龄、世界、身份和性格必答；其余可略过。主问题完成后至多生成两个可选追问。浏览器存储保留原文、题号、追问缓存、请求标识和服务器草稿版本。修改答案会使对应旧追问失效。

编译首次建立草稿，后续修改原位更新同一未发布草稿。服务端恢复明确的作者设定，保存版本化访谈来源。模型根据作者提供的性格扩写解释、不同情境下的表现与可能的行为例子，写入结构化人格描述；例子表达可能的行为，不构成已发生的经历。角色生成请求使用实际所选模型声明的输出上限，模型能力未知时沿用配置预算。

人物小传由模型根据最终生效的结构化人设整理，包括性格解释和行为表现，随角色版本及内容哈希保存。小传本身只用于展示，不作为新增事实写回角色；后续编辑使内容变化时，不显示旧版本的小传。性别和文字年龄兼容旧角色，并进入编辑器和聊天上下文。

`/characters/:id/preview` 可刷新恢复。发布成功后才更新当前角色并进入聊天。冲突重新读取当前版本，必须确认的模型设定逐项处理。详细编辑或审核已经改变了访谈生成版本时，继续提供详细编辑入口，避免重新编译旧访谈覆盖这些修改。

小传页提供「调整人物设定」入口，进入 `/characters/:id/refine`。作者可输入最多 5,000 字符的修改意见，模型结合当前完整人设理解修改范围，再返回更新后的结构化人设与小传。未要求修改的内容从当前版本保留。修改请求包含角色 ID、预期版本和请求标识；提交失败保留反馈，相同请求可安全重试。版本冲突时先阅读最新小传，再确认基于新版本修改。该流程只用于尚未发布、未开始生活和会话的草稿，角色与小传一起成功保存后返回预览。

## 阅读与维护检查

问题、答案、小传和操作控件使用真实 DOM；插画只提供场景与道具。羽毛笔动作应尊重减少动态效果设置，切题和快速重复操作由同步状态锁保护。小传使用独立阅读层，长正文和审核内容必须可滚动、可聚焦，手机布局随安全区域和视口变化。

维护时检查十二题与追问、浏览器草稿恢复、编译及反馈修订幂等、版本冲突、角色与小传保存的原子性、发布、Welcome 角色分流和旧角色兼容。浏览器回归应覆盖长文本、中文 IME、减少动态效果、窄屏、离线失败和恢复、多轮自然语言修改。模型相关 Fixture 测试验证流程边界，内容质量需独立评审；截图、日志及报告保留在工作区外的本地目录。
