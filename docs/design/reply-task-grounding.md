# 回复的主体、依据与正文完整性

## 问题与处理范围

本设计处理以下回复问题：代写时混淆角色、用户与收件人；把用户刚做的事写成角色经历；没有处理历史中未解除的日期冲突；只输出“整理好了”而没有交付正文。JSON 结构合法不能证明内容完成。

实现使用共享生成指导和高置信的空正文检查，复用既有有限修复机制。没有引入每轮额外的模型评审，也没有通过增加状态维度或参数联动处理这些内容问题。

## 主生成与修复共用规则

`REPLY_TASK_GROUNDING_POLICY` 在主生成、普通修复和 fixture 修复使用同一份文本，覆盖：

- 明确代写中的发送者、收件人、角色及第三方。代写正文中的第一人称属于预期发送者；当轮明确的参与者和职责不被角色的一般职业职责覆盖。
- 角色自身的具体近期行动需要对应主体和时间的依据。用户刚忙完、角色有某个目标或当前精力充足，均不能证明角色今天做过某事。
- 区分提议、明确更正和授权变更。确认变更只替代被修改的字段；其余未解除的约束继续有效。不补造第三方的同意或空闲。
- 创意、假设与替代方案允许提出，明确作为建议，不能冒充已定安排或既成事件。
- 请求的正文与必要内容必须进入公开回复文本字段。前言、appraisal 或分块不替代完整 text；人格、简洁偏好和低精力只能影响表达，不能免除任务要求。
- 未知信息保持未知；代拟不等于已经发送或对外保存。

这些是内容生成约束，不能保证模型每次正确理解全部语义或消除所有事实错误。

## 提示预算

新规则作为独立 system segment `01b_reply_task_grounding_policy` 加入，局部预算 600 个估算 tokens。主应用规则段保留原局部预算；新规则没有直接追加进去挤掉原有规则。

新规则使用 required / `globalOverflowPolicy: "error"`：局部额度不足或全局必需内容无法容纳时明确失败，不截断该段。

原有九个 required 段（应用规则、角色身份、核心人格、边界、运行状态、当前时间、回复策略、当前用户消息、输出约束）使用 `globalOverflowPolicy: "preserve"`。它保留既有局部预算处理，包括原先允许的结构化压缩；全局预算阶段必须完整保留这些局部处理后的结果，不能继续裁成省略标记或句子残片。这不宣称原始长人设在局部预算下毫无压缩。

全局输入预算保持原有计算。可选上下文仍按既有规则选择；可选 appraisal 指令可整块撤去后重试。若核心必需内容仍装不下，抛出 `required_segments_exceed_budget`，停止组装。预算回归应验证过小窗口明确失败，以及正常窗口完整保留获准进入的必需内容。

## 高置信空正文检测

`inspectReplyCompleteness` 的作用范围很小：用户明确要求草稿、正文、通知或清单等内容，实际 text 和非空 chunks 却仅为已知的准备/交付引导语。例如“好，整理好了，你可以直接改：”。返回 `REPLY_DELIVERABLE_BODY_MISSING`，同时提供请求依据、实际引导语与修复指引。

它不按长度判断质量，也不推测任意任务遗漏了几个信息点。以下情况不会仅由本检查认定为失败：正常短答案、真实澄清或拒绝、冒号后已有正文、引用或代码、原样复述指定引导语、正文已在另一个展示面中。text/chunks 的不一致仍由现有规则负责。

因此它会保守地漏过未覆盖的表述，不能当作通用任务完成证明。复杂的职责、历史与漏项判断仍依赖生成与既有可选目标复核。

## 一次修复与提交边界

1. 首次回复在 `TurnDecisionService.inspect` 中发现空正文后，进入原有共享的一次 repair 额度，沿用本轮实际获准的上下文。
2. 有效修复正常继续处理。若修复仍为空、不可用，或未通过校验，不用通用寒暄 fallback 冒充交付，而是在提交前返回 `502 / reply_deliverable_incomplete`。
3. 最终提交之前再检查实际待发送文本，覆盖日程呈现、语义过滤或交付改写替换正文的路径。此检查不新增模型调用。
4. 失败不会把该回复、该轮消息对及其附带模型效果提交为成功。相同 clientMessageId 可以重新尝试；不写成功回执阻止重试。正常独立的生活时间推进不属于本检查的事务范围。

失败错误沿用现有 API 错误处理，用户会收到正文生成未完成、可重试的信息。检测的证据也进入原有修复请求记录，保留排查依据。

## 验证方法

单元反例覆盖正文、短答、引用、代码、明确不写与逐字要求；HTTP 集成覆盖一次修复成功、修复再次为空/不可用/无效、失败后无消息及状态效果提交、同请求重试成功，以及晚期替换导致空正文的提交拦截。

真实模型对照协议见 [回复依据与完整性评估](../evals/reply-grounding-completeness.md)。对照只移除新规则，保持同一组已入模数据、状态与回复策略；不补进释放预算后的其他材料。它衡量新增生成规则的影响，不把独立的 repair 检查混为主生成质量，也不冒充完整旧系统对比。新场景在真实调用前固定，失败照实保留。
