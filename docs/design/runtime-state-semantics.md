# 角色状态参数：定义、来源与使用边界

本规范将参数必要性、状态生命周期和回复表达分开检查。一个字段被提示词或条件分支读取，不能单独证明它提高了角色回复质量；参数增删仍需要固定人物、历史和请求的对照实验。

## 数据分层

| 层       | 已有承载                                               | 范围与用途                                                                   |
| -------- | ------------------------------------------------------ | ---------------------------------------------------------------------------- |
| 稳定人格 | CharacterSpec 的 traits、preferences、values、dialogue | 描述长期倾向及其例外；临时情绪不改写人格                                     |
| 当前状态 | RuntimeState 的六维数值                                | 当前模拟条件；影响表达与投入，不证明过去发生过什么                           |
| 长期关系 | relationship.closeness                                 | 有记录的亲近程度；不等于信任、赞同、同意或恋爱                               |
| 具体事件 | PressureEpisode、life threads、decisions、outcomes     | 保留主体、触发原因、来源和事件进展                                           |
| 当轮反应 | InteractionAppraisal                                   | 本轮输出后的主观反应记录，目前主要供日记读取；不自动回写关系或作为下一轮状态 |
| 当轮安排 | conversation plan、daily intents、currentFocus         | 说明当前关注与表达需求；意向不是已经执行的活动                               |

不要把用户的压力或疲惫误记为角色状态。用户、角色和共同事件必须沿用已有 subject / sourceMessageIds 等归属及来源约束。

## 参数定义卡

### 共同生命周期

新角色从应用基线初始化，`initialRuntimeState` 不根据作者人格生成不同的初始情绪。人格差异由人物规格和表达方式提供，不能把瞬时基线当作永久性格。

在动态状态能力开启、世界效果允许提交的模式中，前六维可由模型针对当前互动提出增量，服务端校验、限幅并原子提交。lightweight 不具备动态状态能力。普通聊天当前没有通用的按时间恢复或数值间递归联动。状态在下一次有效更新之前保持，表示模拟器持有的状态，不是持续观测到的心理或生理事实。

`asOfUtc` 与 `revision` 是整份状态的提交信息，不能作为各字段获得了新证据的证明。检查单字段生命周期应读取 effect trace 的 before / after / applied 和触发消息。参数更新次数不能由 revision 增量代替。

| 参数             | 基线 / 范围     | 独立含义                     | 明确不表示                               | 处理决定                                      |
| ---------------- | --------------- | ---------------------------- | ---------------------------------------- | --------------------------------------------- |
| moodValence      | 0.18 / -1..1    | 感受整体的正负方向           | 压力来源、对用户的好恶、特定命名情绪     | 保留；用情绪与激活度组合检验增量              |
| moodArousal      | 0.42 / 0..1     | 当前情绪的激活程度           | 精力、固定话量、必然兴奋                 | 保留；允许平静的开心和激动的不快              |
| energy           | 0.72 / 0..1     | 持续投入所需的精力余量       | 注意力一定下降、心情一定不好             | 保留；低精力描述不得跨维度宣判低 focus        |
| stress           | 0.28 / 0..1     | 当前整体紧张与负荷           | 一定生用户的气、某件事已经发生、事实忙碌 | 保留；与具体 PressureEpisode 的原因和范围分开 |
| socialBattery    | 0.68 / 0..1     | 可用于继续交流的精力余量     | 外向程度、喜欢用户、是否同意继续某话题   | 保留；不固定为冷淡或拒绝，不覆盖明确求助      |
| focus            | 0.70 / 0..1     | 当前持续集中注意力的状态     | 正在做别的事情、当前忙碌、不可打断       | 保留并收窄定义；从忙闲推导中移除              |
| sleepDebtMinutes | 0 / 0..720 分钟 | 有睡眠结算来源时的模拟睡眠债 | 缺乏来源时实际休息充分                   | 保留兼容存储；默认 fuzzy 回复不读取为有效状态 |
| closeness        | 0.10 / 0..1     | 对应用用户的长期亲近程度     | 信任所有陈述、默认亲密许可、回复字数配额 | 单独保留关系生命周期；不从疲劳或压力自动扣减  |

亲近程度有服务端有效互动基线和受限增量。每次有效互动的基准增量为 0.001 × 能力系数：daily 为 0.5，high_fidelity 为 1，lightweight 不启用关系变化；实际提交还受数值边界和每日基线累计上限 0.012 限制。额外关系变化另有单次、每日及能力级别限制。所有数值均为内部模拟量，不能在角色回复中展示为用户评分。

## 睡眠债的可用性

睡眠债不是模型可自由修改的聊天字段。精确日程模式的睡眠结算负责累积、偿还与记录其来源。默认 fuzzy 模式不创建这套精确结算路径，不能将长期沿用的零值当成已知的睡眠情况。

- fuzzy 模式的回复状态投影省略 sleepDebtMinutes 及其定性说明。
- 同一模式的回复策略忽略该值，避免删除文字后仍通过疲劳预算泄露无来源的影响。
- legacy_exact 保留原有读取；持久化字段和历史记录保持可读。
- 如将来接入新的睡眠来源，应明确记录依据、结算范围和重复提交规则，再显式启用读取；时间过去本身不能证明睡眠发生。

## 忙闲与专注分离

fuzzy 日常意图只能证明计划或关注方向，不能证明此刻已经在执行该活动。压力大、专注高或社交精力低也不证明占用状态。

现有数据库 availability 枚举保留 free / interruptible / occupied 以兼容旧记录。没有已观测依据时，free + inferred 仅为存储占位；对外统一投影成 unknown，UI 显示“忙闲未确定”，不将其当作真实空闲。

同一时段已有 observed 的值保留，不会被状态数值覆盖。进入另一时段后，旧观测不继续证明当前忙闲，回到 inferred / 对外 unknown。现有时段粒度并不等于精确活动追踪，新增 observed 写入必须提供自己的证据与当前性约束。

occupied 的显示含义是“正在忙碌”，不使用“正在专注”混同认知状态。意图标题仍可作为关注方向显示，不能因此补出已经开始、完成或持续进行的活动。

## 给主回复与修复模型的状态视图

`RUNTIME_STATE_JSON` 是唯一的当前状态解释入口，保留数值、各维度的一句含义、authority、asOfUtc、revision 与临时性说明。提示词不再同时传入重复 summary 和另一套阈值生成的 stateGuidance。内部兼容或诊断字段不等于模型可见字段。

低精力、高专注等混合状态应能同时成立。描述只说明各维度本身；具体表达结合本轮选取的人格、说话习惯和用户请求决定。无需每轮声明情绪或精力，也无需表现所有维度。状态倾向不应自动覆盖完整回答的需要、让角色编造疲惫原因，或把不同人物压成相同的短答模板。

回复修复从主生成实际获准进入提示的段落中保留同一份完整状态快照。不重新读取最新数据库状态，不恢复主生成因预算或投影未接收的信息。修复上下文必须明确运行状态是本回合瞬时条件，不能作为历史事实或长期记忆。

## 参数必要性审查与新增条件

每次修改参数应记录：含义、来源、生命周期、消费者、与其他字段的区别，以及能被用户感知的预期收益。

审查分为：

1. **源码和数据路径**：确认初始化、允许写入者、提交校验、恢复和读取位置。
2. **轨迹审计**：按字段统计变化、范围、边界停留和跨时间间隔的保持；字段缺失必须标为未知。
3. **读取对照**：固定人物、历史、请求和预算，比较当前读出与移除目标读出；检查派生描述、策略和修复是否残留。
4. **行为评审**：同时观察状态一致性、人格差异、任务完整性、事实依据与自然表达。输出变化不等于输出改善。

可复用 `apps/server/src/scripts/runtime-state-lifecycle-audit.ts` 对已有状态证据导出进行只读汇总：

```powershell
pnpm exec tsx apps/server/src/scripts/runtime-state-lifecycle-audit.ts evidence.json new-report.json
```

输入为 rows，每项包含 branchId、turnId、actualPrompt.runtime、commitEvent 的 recordedAtUtc / before / after。完整导出中的其他字段会被忽略；报告不输出用户话语。每个分支须保持时间顺序，不允许重复回合；输出必须是新文件。新报告保留输入 SHA-256，缺失数值不补零，也不从更新时间猜测恢复。

模型对照协议见 [状态参数读取审查](../evals/runtime-state-audit.md)。小样本单模型实验只提供探索性证据，不能把关键词命中、测试通过或数据正常传递称为“活人感已提升”。

新增参数必须满足：已有数据不能表达反复出现的问题；有独立定义、来源和生命周期；对照显示有可感知收益。兴趣优先使用带对象的 preferences / goals / intents；即时不适优先用有触发来源的 appraisal；受理解感优先保留在具体 pressure episode。不要重复增加无对象的全局兴趣度、烦恼度、信任度或受理解度。

## 已知局限与后续门槛

- 通用时间恢复仍未建立。自动把短时状态拉回基线可能掩盖未解决事件，也可能抹去角色本来允许的持续反应。先形成来源与有效期设计、长间隔反例和独立对照，再引入恢复规则。
- 六维变化目前主要依赖模型提案。合法范围、主体归属和提交成功不等于心理归因合理；轨迹审计与内容评审需分开。
- appraisal 是输出后的记录，不会自动提升下一轮连贯性。如增加短期余波读取，必须带作用对象、来源有效性、失效条件及预算选择，不能直接把全部私人反应重新注入。
- 参数之间高度相关或在一份语料中不变，只构成审查线索。删除存储前需评估独立场景和历史兼容，不能据此直接合并所有情绪或容量维度。
