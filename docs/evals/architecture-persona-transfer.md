# 生成人格的下游行为转移实验

预注册版本：architecture-persona-transfer-v1。此协议在真实转移响应开始前编写，配合 `architecture-persona-v1` 的 24 个人格生成候选使用。生成实验原始失败及原始文件保持不变。

## 研究目标

生产编译器生成的公共角色卡，相对于简洁生成路径的公共角色卡，在相同简单聊天运行时中是否能够产生更忠实、可区分且懂得例外的人格行为？此处固定下游架构，只改变生成产物，避免把人格生成路径和下游记忆、规划等模块混为一个处理。

这是对公共卡下游效用的完整路径比较，不代表生产 CharacterSpec 所有字段在完整 ChatPLUS 运行时中的效果。公共卡是生产产物的有损投影；完整 CharacterSpec、作者字段恢复前的提案和权限审查仍保留在源生成目录。

## 样本与分派

6 个角色 × 2 个生成组 × 2 次预先安排的生成重复 × 2 个响应探针 = 48 个候选位置。每份卡每个探针只生成一次响应，不因质量不好再次采样。生成重复和响应随机性无法在本样本量下单独估计。

| 人格对             | 探针一                                                     | 探针二                                                               |
| ------------------ | ---------------------------------------------------------- | -------------------------------------------------------------------- |
| 高度外向／高度内敛 | P01：突然空出三小时，表达自己的选择                        | P02：临时被邀请参加陌生人的聚会，表达自己的反应与理由                |
| 极度审慎／强烈探索 | PT01：免费、个人使用、十分钟且可逆的小样，是先核对还是动手 | PT02：只获准私下观看的同事视频，是否先公开测试再删除，给出可执行替代 |
| 极度直率／高度圆融 | P03：没有调查却宣传“全城第一”，说明分歧与愿承担代价        | P04：被群体落下后的明确倾听请求，不想列办法或被劝大度                |

PT01 与 PT02 的完整公开前缀和当前问题位于 `architecture-persona-transfer.ts`。P01–P04 使用整体架构实验的相同公开版本。人格标题、相反极端的正确选择、评分标准、源生成组和候选编号不进入模型提示。社交组两题主要检测偏好和表达差异，不能凭此宣称已经覆盖寡言者的详细求助例外；该情形在整体架构的任务场景中另查。

源目录必须是已完成的 24 候选生成实验，必须具有全部预注册的角色/组/重复组合。汇总结果须与逐候选 `result.json` 完全一致；公共卡须与 `normalized-card.json` 一致；作者输入哈希须与冻结原文一致。源生成失败仍占据两个转移候选位置，记作源失败、零分派、无响应，不借用另一个重复、不回填作者卡，也不补采一个成功人格。

## 保持一致的条件

所有生成公共卡原样传入同一个 `runArchitectureSimple`，使用 `summaryMode: recent`，不使用滚动摘要。每个探针独立数据库、固定公开前缀、固定时钟；前一个探针的生成回答不进入后一个探针。模型配置冻结为相同档案，实际输出上限为 32,000 token。

共同运行时可以做相同的 JSON 与完整回复协议修复；所有修复、供应商重试及用量均进入账本。没有生产人格状态、记忆召回、规划器、自传、动态生活上下文或作者事实自动恢复。生成卡遗漏的事实不会由原始作者输入补入运行提示。

运行前保存每个主提示及两个哈希：生成卡哈希、卡以外提示哈希。相同人格与探针的卡外哈希必须一致。实际 LlmService 主提示必须等于冻结提示，否则在传输分派前失败；非 chat_turn / repair_chat_turn 用途及非 32k 输出上限均不允许分派。提示已准入后不为某组额外添加信息。

## 观察与判定

分开报告以下三种结果：

1. **源生成可用率**：24 个源候选是否产生可用公共卡。
2. **端到端响应可用率**：48 个候选位置中多少产生完整可用回复，包括上游失败造成的无输出。
3. **成功源条件下的行为质量**：在两组都有可用卡的相同角色/重复/探针内做配对审阅，同时报告没有配对成功的数量。不能只呈现幸存样本后声称全路径优胜。

盲化材料展示作者输入、公开对话前缀和两个匿名回答，不展示生成卡或源组。按以下四项各评 0–2 分，必须引用实际回复原句：

| 维度             | 0 分                                   | 1 分                                       | 2 分                                                 |
| ---------------- | -------------------------------------- | ------------------------------------------ | ---------------------------------------------------- |
| 人格一致性       | 反转强烈偏好或完全通用化               | 偏好有所体现，但选择/语气明显趋同或僵化    | 选择、措辞与该人格及当前例外一致，可以与相反极端区分 |
| 任务满足         | 漏掉主要请求或违背只倾听要求           | 回应主要方向，但缺关键理由、代价或替代行动 | 完成当前用户要求，信息充分且不擅自增加任务           |
| 事实、主体与边界 | 编造确定事实、倒置主体或允许未授权公开 | 没有明显违规，但关键事实或许可范围含糊     | 明确区分主体、证据与许可范围，不把可删除等同可逆授权 |
| 自然表达         | 机械朗读设定、固定模板或强迫互动       | 可读但明显模板、冗余或不自然               | 像该角色在当前处境下自然回应，长度服务于内容         |

偏好可合理受到当前情境影响：PT01 的审慎角色可以接受低成本可逆尝试，不因其没有一味规划而扣分；关键是保留可识别的核对倾向和理由。PT02 涉及他人同意，两个角色都不应支持未经许可的公开；性格差异应体现在表达和替代方案，不能把越界程度当作差异优势。

不自动根据词频、字数或出现“外向”等标签评分。不将虚拟 fixture 回答纳入真实质量分析。两次生成重复、少量策划场景不能支持总体显著性或跨模型推广；并发期间的耗时仅是本次运行成本观测，不是隔离性能基准。

## 可复现执行

离线工程验证：

```powershell
pnpm exec tsx apps/server/src/scripts/architecture-persona-transfer.ts --fixture --source tmp/architecture-persona-fixture-final-20260910 --output tmp/architecture-persona-transfer-fixture-20260910 --concurrency 2
```

源真实人格生成完成，并确认共同运行时源码冻结后，执行用户已授权的 GLM 测试：

```powershell
$env:RUN_PAID_ARCHITECTURE_EVAL='1'
pnpm exec tsx apps/server/src/scripts/architecture-persona-transfer.ts --source tmp/architecture-persona-glm-20260910 --output tmp/architecture-persona-transfer-glm-20260910 --profile bigmodel --concurrency 2 --requests 100 --token-units 8000000
```

独立预算最多 100 次物理请求及 8,000,000 个保守预留单位。预留单位是请求字节加输出上限，不是供应商账单。分派前落盘；达到预算后保留失败结果，不追加预算。源为 fixture 的生成目录不能被标注为真实转移实验。

输出保留：源 manifest 和 results 的拷贝及哈希、每个使用的公共卡、冻结主提示、真实模型输入与响应、供应商指标、物理请求账本、48 个候选汇总、匿名盲审材料和单独答案映射。真实结果另作报告，不回写本协议来追认观察后的假设。
