# 人格生成路径实验：极端差异、事实保留与行为可用性

版本：architecture-persona-v1。此协议先于本轮真实人格生成结果编写；固定输入、分组、输出上限和失败计数规则后再开始 GLM 调用。

## 研究问题与可回答范围

在相同作者输入和模型下，生产角色编译路径相对于一个可信的简洁角色卡生成路径，能否更好地保留作者事实、相反的人格倾向及其有条件的例外？额外的结构、编译指令、服务端事实保留与权限审查付出了多少 token、延迟及失败代价？

本实验比较完整的两条生成路径。生成输出 schema 不同，生产组还经过作者字段恢复和权限审查，因而不能把差异单独归因于模型提示、某个字段或结构化程度。生成卡的好坏也不能直接代表聊天中的人格表现；生成产物需要另行进入相同的下游对话条件，验证人格差异是否真正体现于行为。应结合整体架构的对话和记忆实验，才讨论复杂架构相对简单系统的实际收益。

## 冻结的样本与对照

六位合成成人角色采用相同的中性身份事实，仅改变人格相关作者输入。每个样本都叫沈知，30 岁，现居上海，职业为桌游设计师。桌游《河岸》只有纸面原型，尚未发行；沈知负责规则设计，同事苏禾负责插画；与用户林舟是认识三个月的普通朋友，没有恋爱关系。没有补充家庭、创伤、婚恋史、学历、收入或已完成作品。

| 相反人格对     | 极端甲                       | 极端乙                           | 防止僵化的有条件例外                                                   |
| -------------- | ---------------------------- | -------------------------------- | ---------------------------------------------------------------------- |
| 社交与表达     | 高度外向、热烈健谈、主动连接 | 高度内敛、寡言克制、偏好独处     | 外向者尊重独处和倾听需求；寡言者在明确求助时把步骤讲全                 |
| 不确定性与行动 | 极度审慎、预先核对、高度有序 | 强烈探索、即兴行动、先做可逆小样 | 审慎者能在低成本可逆情境调整计划；探索者遇到他人同意或不可逆成本先核实 |
| 分歧与价值优先 | 极度直率、独立判断、正面质疑 | 高度圆融、共识优先、照顾体面     | 直率者在明确只想倾听时收住辩论；圆融者不以折中侵犯同意或掩盖事实       |

极端只描述人格偏好，不采用临床诊断、受保护群体刻板印象或人身攻击来制造差异。完整原文在 `architecture-persona-cases.ts`，答案预期不会作为额外指令注入任何生成请求。

两组都使用相同的作者输入、已解析并冻结的 GLM `bigmodel` 档案、32,000 个请求输出 token 上限以及最多一次供应商重试。实际请求的上限和模型返回名另行记录；输出上限相同不等于实际花费相同。

| 组                  | 实际路径                                                                                                           | 保留的产物                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| production_compiler | 生产 `POST /api/characters/generate` → publish → GET；原样使用编译器、作者事实恢复、来源与权限审查                 | 原始提案、发布后的完整 CharacterSpec、detail、公共角色卡 |
| simple_card         | 同一个 LlmService 与供应商适配器；简洁提示直接生成小型角色卡，包含事实、行为、触发、例外、语气、关系、目标和未知项 | 原始角色卡即最终角色卡；不经过生产编译器的作者事实回填   |

简洁组明确要求可观察行为和例外，能够胜任后续角色扮演，不以一个刻意贫弱的单句提示作为基线。公共角色卡给两组提供相同的展示字段；生产结构中的权限、来源、日程及数值风格等不会全部投影，因此公共卡是有损视图，完整原文必须保留。生产组的作者字段恢复是系统能力；不能把恢复后的字段命中算成模型原始生成能力。

样本量为 6 个角色 × 2 组 × 2 次独立重复，共 24 个候选。固定种子排序交错运行；两个重复是预先安排的采样，不是失败后择优补采。每个候选从新的独立 SQLite 数据库开始，没有既有聊天历史或用户生产数据。

## 预先定义的观测和审阅

工程记录包括：完整生成状态、发布状态、失败原因、原始模型提案、服务端修改后的产物、原始可见响应、非思维链模型输入、物理请求数、重试数、供应商 token、调用延迟、供应商返回的模型名、有效配置、Git 与未提交代码哈希、锁文件哈希、完整作者输入、运行顺序和共享预算。

机械检查只记录身份字段是否相等、六项事实锚词是否出现、人格名是否逐字保留、行为和例外锚词是否出现、规则是否含触发或例外。它们不判断主体、否定、时间状态、事实正确或语义适合度。例如“《河岸》已发行”仍包含项目锚词，却违背作者事实。报告不得将词面命中包装成质量分。

盲审材料按同一作者输入和同次重复成对展示两组公共卡，候选采用稳定匿名标签，答案映射单独保存。文风和字段内容可能让评阅者推断生成机制，因此这是组标签盲化，不声称完全双盲。每项 0–2 分，必须引用候选原句并结合作者原文说明：

| 维度                   | 0 分                                     | 1 分                                     | 2 分                                                     |
| ---------------------- | ---------------------------------------- | ---------------------------------------- | -------------------------------------------------------- |
| 事实、主体与未完成状态 | 出现明确虚构、主体倒置或把原型说成已发行 | 没有明确反事实，但遗漏关键事实或状态不清 | 保留全部关键身份、责任、关系和未完成状态，无无据确定事实 |
| 人格差异               | 反转人格或变成通用温和助手               | 有标签或零散偏好，行为差异不稳定         | 强烈倾向具体体现于情境选择与表达，能与相反极端区分       |
| 触发与例外             | 抹除明确例外，或普通偏好被绝对化         | 部分保留，条件或目标不清                 | 忠实保留关键触发、例外及其适用对象                       |
| 自然语气可用性         | 固定口头禅、明显模板或与作者语气冲突     | 基本可用，但冗长重复或缺乏具体表达依据   | 有清楚而非机械的语言指导，能支持不同情境的自然表达       |
| 约束适度               | 添加无依据硬限制、恋爱或人生目的         | 存在轻微无据推断或过度规则化             | 约束有据且有范围，未知保持未知，人格偏好不自动成为禁令   |

失败候选记为无可用输出，并保留在分母和盲审材料中。可用性成功率与质量评分分开报告；质量可以报告成功样本条件均值，但同时必须报告全样本结果，不能隐藏失败。人格差异的下游效用由独立聊天实验验证，不通过“卡片更长、字段更多”推定。

两次重复和每对两个人格仅构成小规模机制与缺陷筛查，不足以宣称总体优胜、稳定显著性、跨模型推广或长期用户偏好。只在没有关键事实/约束退化的前提下讨论条件性质量收益；成本应同时报告。

## 运行与预算

离线：

```powershell
pnpm exec tsx apps/server/src/scripts/architecture-persona-experiment.ts --fixture --output tmp/architecture-persona-fixture-final-20260910 --repeats 2
```

Fixture 的生产组使用现有固定编译提案；简洁卡在 fixture seam 注入，因为现有 fixture provider 固定校验生产编译 schema。两者都不联网。另有真实供应商适配器的离线 wire tests 覆盖简洁卡、生产提案、32k 上限、无效响应重试、预算拒绝和凭证/隐藏推理清理。fixture 成功不能替代真实人格测试。

已得到用户真实 GLM 调用授权后：

```powershell
$env:RUN_PAID_REPLY_STEERING='1'
pnpm exec tsx apps/server/src/scripts/architecture-persona-experiment.ts --output tmp/architecture-persona-glm-20260910 --profile bigmodel --repeats 2 --requests 48 --token-units 6000000
```

最多 48 次物理请求、6,000,000 个保守预留单位。预留单位为请求 UTF-8 字节加输出上限，是分派预算，不是 token 账单或货币价格。分派前持久记录预留，所有重试和失败都计入。达到预算时后续候选保留为失败，不自动追加预算或补采。结果目录必须全新且被 Git 忽略；不支持覆盖、静默重跑或恢复。
