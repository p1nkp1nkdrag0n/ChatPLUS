# Chat context window and descriptive persona evaluation

The application targets a **258,000-token total chat window**. This is an application admission limit, not a declaration that every provider supports that capacity. Main generation uses the smaller of the selected model's reported context capacity and 258,000, then reserves the actual requested output allowance and 2,000 tokens for transport/schema overhead. When model capacity is unknown, the existing conservative 32,000-token fallback remains.

For the configured GLM profile (reported capacity 1,000,000, main output request 24,576), the assembled input allowance is **231,424 estimated tokens**. A 128,000-token model gets 101,424 input tokens; the application never expands the provider's capability metadata to fit the requested window. Estimates use the shared conservative Unicode estimator; provider-reported usage remains the evidence for actual billed token counts.

Before this change, main input had a separate 24,000-token cap. Raw history was selected with 8,000/12,000-token soft/hard limits, then limited to 20 messages by default (200 even for a larger explicit request), and finally compressed into a 3,000-token recent-history segment.

The raw-history defaults are now **200,000 soft / 232,000 hard**. These are candidate-selection limits: they count message content before JSON framing and before other prompt segments. The final model-aware global input limit still applies. Existing explicit `CONVERSATION_SOFT_TOKEN_LIMIT` and `CONVERSATION_HARD_TOKEN_LIMIT` environment settings remain overrides. The 24-hour full-verbatim period, 3,000-token minimum tail and 12 minimum recent turns remain minimum retention preferences, not maximum history limits.

When the server supplies its input allowance, recent history can use the remaining global prompt space, after required instructions and higher-priority evidence. There is no implicit 20/200-message cap. Explicit `maxRecentMessages`, including zero, is still honored. A standalone assembler caller without a model budget retains the bounded default segment allowance. Global compaction keeps complete messages; it does not promise that every selected message or complete user/assistant turn always fits.

Long-term memory remains relevance-selected evidence with its own limits. Increasing the chat window does not make every stored memory or autobiography authoritative, nor does it imply all stored history is sent on every turn. Larger default retention also delays checkpoint creation until the candidate window needs to omit history. The small-window long-run regression uses explicit constrained limits to continue testing checkpointing and restart behavior.

For descriptive persona experiments, keep the same identity, facts, numeric dialogue traits, state, user inputs and model settings. Change only the authored behavior description. The original terse test character already had an 80-character author-guidance paragraph; it was not a one-word label. The expanded candidate describes attention, judgment, when speech naturally stops, dry humor, care, and willingness to explain when asked, without imposing word/sentence/bubble quotas or seeding answers to the test topics.

Use a 2×2 continuous design: original versus expanded description, each under previous versus expanded context policy. Record actual retained history and prompt tokens: an eight-turn conversation may not hit the previous limits, so changing a ceiling does not establish a context benefit. Evaluate context retention separately with identical synthetic long histories and facts placed at early, middle and late positions; inspect both the sent evidence and actual model answers. Keep naturalness judgments separate from length distributions, factual accuracy and explicit instruction adherence.
