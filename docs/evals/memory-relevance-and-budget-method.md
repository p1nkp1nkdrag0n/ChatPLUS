# 记忆相关性、回复控制与上下文预算实验方法

本协议定义合成记忆探针、表达控制消融和上下文预算检查的方法。固定配置、场景与评分口径后运行；实际模型输出、评分与报告保存在本地忽略目录。

## 记忆召回 × 提及门控

```powershell
pnpm test:memory-relevance:fixture --output tmp/memory-relevance-NEW
```

输出目录必须是仓库内被 Git 忽略的新目录。已有实验不会被覆盖。命令不读取模型密钥、不调用模型或 embedding API，不使用用户数据库。

| 实验组 | 候选评分                             | 使用门控   |
| ------ | ------------------------------------ | ---------- |
| R0U0   | 当前词面召回                         | 旧词面门控 |
| R0U1   | 当前词面召回                         | 共享相关性 |
| R1U0   | 词面 + 绑定到证据的 fixture 语义分数 | 旧词面门控 |
| R1U1   | 词面 + 绑定到证据的 fixture 语义分数 | 共享相关性 |

R0/R1 共用当前实现中的来源、标识符、生命周期、命名空间和时间过滤，不是历史提交回放。语义分数是显式合成输入，不能凭它扩大候选数据库范围、制造来源，或将相似但不同的编号视为同一个实体。未来接入真实 embedding 时，仍需实现并验证索引增量更新、候选发现、部分索引覆盖、查询绑定和模型/索引版本，不能把本命令的结果当成这些工作的验收。

12 个场景 × 4 组，共 48 个确定性探针，覆盖中英文无词面重合的改写、未建立语义信号的新记忆、相近编号、过期、被取代事实、命名空间、无证据记录、撤回、近期重复、倾听偏好和无关高重要性记忆。标注区分：应召回、允许显式提及、不得召回、不得使用。禁止项和意外提及使 CLI 失败；召回与提及遗漏分开报告，以定位损失来自哪一层。

产物包括：

- `manifest.json`：固定时钟、阈值、组别、完整合成场景、语义分数来源、Git 提交、相关源文件 SHA-256 和场景 SHA-256。
- `results.json`：每个场景/组的选中记忆与证据、共享相关性绑定、评分、提及权限、遗漏原因和约束检查。
- `comparison.md`：四组召回遗漏、提及遗漏、意外提及、禁止召回和禁止使用分别计数。

不将这些合成探针当作独立用户会话样本，不计算自然感得分、统计显著性或真实模型改进百分比。

## 上下文预算与展示

`unicode-heuristic-v1` 是模型无关的规划估计，不是 tokenizer，也不是所有模型的严格上界。诊断保留估算方法及估算值，provider 返回的真实 usage 单独保留。预算变化可能使中文或 JSON 较多的上下文更早触发压缩；应通过 trace 检查实际准入的段落与证据，而不能继续拿旧估算数与新估算数直接比较。

证据、近期原文和自传按完整记录压缩，当前用户消息的结构完整性继续受保护。实际 usage 可能包含消息封装、输出 schema 等传输内容，不能要求其与正文估算相等。

当前产品将气泡展示与历史消息存储分开：`DatabaseStore.insertMessage` 保存整条回复，气泡记录在元数据；聊天历史选择读取整条 `content`，前端 `resolveMessageDelivery` 只决定如何展示。后续进行展示体验实验时，应冻结相同回复文字与消息 ID。

## 后续实验边界

经作者审核的话语样本、人物区分度盲评、低复杂度完整系统基线、上下文注入位置/持续、主动话题价值排序、角色公开简介与社会关系仍是后续独立实验。当前没有足够实测证据支持同时启用这些机制或改变产品人格。应先用固定前缀回放观察各实验变量，再开展各自独立写入的长期会话验证。
