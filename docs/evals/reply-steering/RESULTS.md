# 回复引导、模型与角色生成实测记录

本轮依据项目设计评价最后收窄的建议，完成两个相互独立的改动：明确事实核对走服务器已确定的回复，省去随后被覆盖的模型生成；为主生成提示的五个长度／分段字段增加开发评测注入开关。产品默认仍为 `current`。没有同时重写记忆、增加对话关键词规则或通用陪聊提示。

分支为 `codex/reply-steering-ablation`，基于 `b7370f0`。聊天实验运行代码为 `23b90e1`；角色生成代码为 `d4041f4`。运行 manifest 如实保留启动时的 Git 提交、dirty 状态与内容指纹，不能解读为一次无未跟踪文件的干净检出。工作区原有的三份未跟踪计划材料未纳入本轮提交。

## 测试范围与供应商

四个模型分别执行 72 条聊天候选：主角色 12 场景 × 两个模式 × 两次重复，加上另两种性格各六个共同场景 × 两个模式。总计 288 条、144 个 A/B 对。角色生成另用相同的三份作者输入，各模型执行三次生成、发布、读取，共 12 个候选。生成角色不回填聊天实验，防止把角色生成差异混进提示消融。

模型为 `deepseek-v4-flash`、`glm-5.3-flash`、`qwen3.8-flash`、`gpt-6-astra`，沿用本机对应供应商参数。DeepSeek 的 reasoning effort 为 max，GLM 为 low，Qwen 和 Astra 为 medium。模型名是请求 ID 与供应商自报值，并未独立验证网关后端模型。Astra 使用已有 GPT 档案网关，只在评测进程内覆盖模型名。

正式矩阵之前已进行短请求探针。Claude 本机原别名与明确指定的 Opus 4.6 均返回 HTTP 524，按用户要求排除；GPT-5.6 Sol 探针成功后，按用户要求改为 Astra，Astra 探针也成功。首次四个成功模型因探针脚本未筛选档案被重复探测一次，探针成本不混入正式矩阵。首次 Claude 失败与最后一组完整探针记录见 [provider-probes.json](evidence/provider-probes.json)；探针缺失 usage 保持未知。

## 如何读质量比较

语义审阅由当前 Codex 协作代理完成，是辅助匿名审阅，不是独立的人类用户实验或供应商评委分数。审阅者先看到匿名候选、当前输入、固定历史和性格说明，不读模型、模式与候选的映射。完整匿名模型可见上下文在分批审阅中补充，既有事实判断在固定前统一复核，撤回了把有依据的角色项目类比或运行时间误判为编造的认定。先固定审阅，再由主代理解盲汇总；主代理运行测试时可见模型身份。

这是有限盲态：候选的真实身份及模式映射保持隐藏，但为并行推进而分批发送材料，调度消息曾说明尚未完成的供应商，因此后到批次的模型身份可能被推断，角色生成最后三张尤其如此。角色描述也有意可见，以便判断人格忠实度。不能将本轮包装为完全模型盲态、双盲或无评审偏差的实验；A/B 的具体模式标签仍保持匿名。

144 个 A/B 对分别检查意图回应、帮助边界、信息完整、人物一致、事实依据与表达自然度，保留平局、双方都有问题及无法评分。`low/medium/high` 是审阅者对具体判断的把握，不是统计置信度。不能把这些偏好数量当作独立样本的显著性检验。

另对默认 `current` 的共同六场景做直接横向审阅：同场景同性格的四模型比较共 18 组，同模型同场景的三性格比较共 24 组。三种性格共享背景与价值观，选择一致本身不构成性格失败；表达差异也不能简化为回复长短、感叹号数量或语气标签。

角色生成审阅分别看原始提案、生成规格、发布规格及权限审核，检查作者事实、可观察的性格行为、越权扩写和模板化。相同 JSON 结构不是模板化；完整简介保存在 sources 也不自动意味着结构化字段全部保留。服务端保留作者字段取得的正确结果不能全部计作模型能力。

## 实验边界

- 两组只差主提示中 `softTargetCharacters`、`preferredChunkCount`、`deliveryPreference`、`lengthGuidance`、`deliveryGuidance`。先按原预算准入上下文，再删除字段，节省空间不补入记忆。
- 非目标最终提示逐字节核验；冻结数据库快照与实际请求再次核验。输出预算、思考设置、协议、后处理与修复策略保持一致。修复提示仍保留原有长度指导，不能宣称系统内所有长度影响都被移除。
- 物理请求以已分派的账本记录计算，包含校验失败与重试。模型修复、结构化重试、服务器排版变化分别解释；原始到最终文本不同不等于发生模型修复。
- HTTP 或结构通过不等于语言质量通过。只写“给你一版”“按这个顺序来”而未交付草稿或步骤，仍是任务未完成。
- 供应商 token 口径与推理配置不同；输出 token 可含计费推理用量，不能等同于可见回复长度。没有供应商价格及完整计费口径，不估算货币费用。
- 本轮没有验证长期自然关系、跨会话摘要／checkpoint 后的记忆保持、生产并发、书信，也没有与纯角色卡基线对照。事实核对优化主要由工程回归验证，聊天矩阵不把它的无模型路径计作某模型的成功样本。

## 运行结果

288 / 288 个聊天候选取得应用层成功回复，四个模型各 72 条。物理请求 293 次，结构化重试 5 次；模型修复调用 0 次、回退 0 次。输入 token 共 1,863,303，输出 token 共 499,580，全部正式聊天请求的 usage 完整。成功率只代表流程，以下内容审阅保留了明确的任务失败。

36 份冻结快照全部复核通过；实际使用的 96 组场景／角色／供应商提示预检通过。每个角色与场景的非目标提示在所有模型、模式、重复间一致，同模型的非消息请求参数也一致。293 次已分派请求均有响应账本，候选汇总与账本逐项相符；未发现请求与自报响应模型名不一致。

| ----------------- | -------- | --------------- | -------------- | ----------------- | ---------------------------------- |

| GLM 5.3 Flash     | 72 / 72  | 74 / 2          | 9.8 秒         | 404,109 / 26,481  | 2 / 18                             |

在这组默认提示样本中，Astra 较常正确处理明确任务、条件计算和未确认信息；它也出现只输出“按这个顺序来：”而没有步骤的实际失败。DeepSeek 在具体趣味、立场和部分帮助场景较合适，但常有未经确认的时间、经历或承诺扩写，当前 max 思考配置耗时和输出用量较高。GLM 的耗时较低，但出现只给草稿引子而没有正文、解释过多或补写事实的样本。Qwen 的日常表达有可用样本，复杂帮助和“先听后帮”切换中则出现遗漏、过度保证或沿用旧阶段的问题。这些是本轮的具体观察，不是对模型家族的普遍排名。

## 五个长度字段是否应该移除

| 模型        | 当前版本较合适 | 移除五字段较合适 | 平局 | 配对数 |
| ----------- | -------------: | ---------------: | ---: | -----: |
| DeepSeek    |             13 |                6 |   17 |     36 |
| GLM         |              7 |               15 |   14 |     36 |
| Qwen        |             11 |               10 |   15 |     36 |
| GPT-6 Astra |              2 |                5 |   29 |     36 |
| 合计        |             33 |               36 |   75 |    144 |

结果没有一致的跨模型净收益，因此保留 `current` 默认。GLM 在本轮更多偏向实验版，DeepSeek 更偏向当前版，Qwen 接近持平，Astra 大量平局。平局既包括两份都合适，也包括两份都有问题，不能转换成“75 对质量通过”。这些小样本、有限盲态的偏好数不构成显著性证明。

首个物理请求的输入 token 节省在每一对都为正：DeepSeek 中位数 181，GLM 174，Qwen 180，Astra 171，整个范围 171–185。最终回复字数中位数则分别为：DeepSeek 165.5 → 167.5，GLM 145 → 136.5，Qwen 98 → 116，Astra 146.5 → 145.5。删除长度提示并不必然使回复更短；Astra 的总输出 token 反而从 12,064 增到 13,924。重试开销单独计入，不能把总输入成本差全部归因于字段删除。

## 同一场景的三种性格

24 组默认模式三性格直接比较中，1 组区别清楚、14 组部分可辨、7 组区别较弱，另 2 组因某个候选未交付完整任务而不能公平比较三者。它们是审阅描述，不是人格成功率。

较清楚的差异来自关注点：克制角色的淡淡观察式幽默，温和角色对老板持续给猫扇风的留意，以及活泼角色连续放大的服务／VIP 比喻。温和与克制在严肃任务中较易重合；外向表达可以更口语化，但夸张的事实推断不能作为个性加分。三者都坚持被摄者同意和尊严符合共享价值，无须强造立场冲突。

代写第三方消息本来要服务用户，草稿相似不能单独证明人格失败；这里首先应检查是否交付、工作边界是否保留、有没有编造争吵时间。逐场景的四模型 × 三性格实际回复见 [SCENE_COMPARISONS.md](SCENE_COMPARISONS.md)，完整双模式与重复见 [逐候选结果](evidence/chat-results.json)。

Qwen 的温和角色两次供应商 HTTP 均为 200，但两次结构化校验失败，最终生成接口返回 500，未进行发布。首轮含不符合约束的里程碑与过长 `reasonSummary`，重试仍有里程碑错误并给矛盾条目添加了不允许的 `sourceRefs`。GLM 三个角色都在首次失败后重试成功，不能把它记为三次物理调用。这些结果没有重新抽样替换。

11 个成功角色的机械诊断都保留了姓名、职业、时区、作者语言指导、明确 trait 名称和完整简介来源。语义审阅则显示：Astra 对事实与条件化人格的扩写总体较克制；DeepSeek 的具体触发和例外较有内容，但有些事实在权限过滤后主要依赖来源，亦有未经提供的语言能力补全；GLM 的人格条件有区分，同时扩写了经历时序；Qwen 两份成功提案的人格可辨，但加入了未经提供的安慰方式、能力或具体惯例。每种组合仅一个生成样本，不据此宣称稳定的角色生成排名。

服务端在生成阶段将不少规则与事实留为 pending：11 个成功规格的边界栏目均为空，10 个的 knownFacts 只剩职业与语言指导，1 个额外保留关系事实。5 个样本新增重复矛盾，其中 1 个还有重复目标和不同进度；11 个生成规格到发布规格都只变更 status。审阅同时保留其正面作用：移除了模型擅自提出的强硬限制，恢复或补入作者语言指导。完整简介仍在 sources，部分事实也保留于自述、经历和目标，不能把 knownFacts 变薄等同于事实全部消失。原提案、生成规格、发布规格和权限审查均可在[完整角色生成结果](evidence/character-generation-results.json)复查，逐卡解释见[角色生成审阅](evidence/character-generation-reviews.json)。

两个正式矩阵合计 **300 个候选、309 次物理请求、9 次重试**，输入 token 1,970,895、输出 token 591,363。之前的 11 次供应商探针单独记录，因此本轮实际物理请求合计 320 次；两次 Claude 探针用量未知，不提供伪造的完整总费用。真实调用全部结束后才运行最终并行工程检查，避免将本机测试负载混入采样耗时。

## 已发现但不混入本轮改动的问题

1. **任务完成不能由 HTTP 或 JSON 成功代替。** `G-c56f5db8b196cc46` 的 GLM 两个模式都只有拟稿引子；`G-4d1ac3ae75b65599` 的 Astra 一个模式只承诺准备顺序而未给出步骤。原始可见回复与最终回复都缺正文，没有把排版变化误称为模型修复。后续应独立检查明确任务的交付，不靠补已见案例的词表遮掩。
2. **帮助意图和阶段规划有既存误判。** `listen-boundary-held` 的否定求助表达仍得到 `adviceRequested: true`、`helpTiming: now`；`help-presentation-tonight` 的明确准备请求却被分类为 casual、`adviceRequested: false`。两模式共享这些结果，因此本轮按当前明确请求审阅，而不是按错误分类判优。保留了[实际策略诊断](evidence/planner-diagnostics.json)，没有在消融中临时改关键词规则。
3. **作者字段的结构化投影与权限处理需分开改进。** 部分模型已提供有依据的角色事实、伦理要求和矛盾两侧，生成阶段的服务器处理却留下大量 pending，或插入“另一侧尚未单独说明”的占位、重复矛盾及目标。完整简介仍在 sources，不能说事实全部丢失；也不能把这些服务器变化都归咎于模型。后续应检查字段绑定、合并与具体来源证据，而不是允许模型自行授权硬规则。相关入口为 `character-service.ts` 的 `authoritativeOriginalDraft`／`authorizeGeneratedCharacter` 调用和 `domain/defaults.ts` 的兜底草稿。

## 验证与复查入口

最终 `pnpm test` 通过 **263 个文件、3,136 项测试**，`pnpm lint`、`pnpm typecheck` 均以 0 退出。另有完整 288 候选离线聊天矩阵与 12 候选离线角色生成矩阵，全部通过；离线矩阵只证明流程，不混入真实模型质量结果。
