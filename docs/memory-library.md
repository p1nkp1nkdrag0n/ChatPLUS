# 记忆档案室：架构与维护指南

记忆档案室把角色与用户的真实对话整理为角色第一人称日记，是现有记忆系统之上的阅读层。日记可以表达欣赏、不赞同、疲惫、不自在或矛盾，也可以按角色兴趣略写；它不会替用户写日记，不要求每篇都温暖积极。

## 用户入口与书籍交互

- 主导航“记忆”进入 `/memory-library`；角色范围入口为 `/characters/:characterId/memory-library`。页面支持按角色、年份和月份找书。
- 点击“写进日记”，选择角色和日期，从这一天已存储的聊天生成手记。浏览器本地 IANA 时区决定日界线；已有手记更新时沿用原时区。
- 一本书对应“角色 × 月份”，一篇日记对应一天。书卷由已成功生成的日记聚合，不是另一份独立保存的正文。
- 交互有两个阶段：点击书脊先把书取出，停在封面；点击封面才展开阅读。阅读中支持翻页和目录跳转，合书后才放回书架。
- `DiaryBook`、`useBookMotion` 管理取书、开合与翻页。动作门控防止连点造成竞争，支持减少动态效果。分页按实际 DOM 测量，阅读位置按日记 ID 和正文偏移保存，避免字体或视口变化后只靠旧页码定位。
- 桌面保留正视双页与翻书动画。手机以 402 × 874 逻辑尺寸为设计参考，采用两行筛选、可横滑的宽书脊、独立全屏书籍层和单页阅读；上一页／下一页直接切换内容，不播放纸张翻转动画。手机分页按整页宽度和可用高度测量，正文使用 16–17px；日期目录跳转后自动收起。
- 手机抽书期间锁住背景滚动与导航焦点，放回后恢复原书架位置；页头和底栏只隐藏而不改变背景书架的几何位置，保持归位动画对齐。实际尺寸跟随 Android 视口、安全区域和屏幕旋转，不模拟 iOS 系统栏。
- 原始来源发生变化时，旧手记仍可阅读并提示更新；重新整理成功后显示新版本，失败不会清空旧正文。

前端实现集中在 `apps/web/src/pages/MemoryLibraryPage.tsx`、`components/memory-library/`、`api/diaries.ts`、`styles/memory-library.css` 和 `styles/memory-library-mobile.css`。

## 从对话到日记

```text
重要回合的可选 interactionAppraisal
  → 服务端核对用户原文、最终回复、角色与状态快照
  → interaction.appraisal.recorded + 来源有效性依赖
                                      ↓
用户选择角色、日期和时区
  → 收集真实分享 + 必要对话上下文 + 历史 world_effects + 有效 appraisals
  → 冻结来源 hash、角色版本、目标日记版本与模型选择
  → diary_generation：生成 title + 带来源 ID 的 paragraphs
  → 服务端检查结构与来源范围
  → diary_review：独立审查事实、时态、主体与角色感受边界
  → 如不通过，最多一次定向修复，再审查
  → 事务内复核来源与版本未变化
  → 新 revision 入库，切换当前版本，更新请求结果
```

`InteractionAppraisalService` 保存的是有明确 schema 的角色模拟感受，不是模型隐藏推理。它包含定性感受、互动态度、受限私下观点、实际公开回复摘录，以及当轮角色版本、好感度和运行状态。记录必须对应仍然有效的用户和助手消息；已有来源被纠正或失效后，日记读取不会继续采纳该记录。

`DiaryRepository.material` 以用户本地日期的半开 UTC 区间选取该角色的用户分享。它保留相关回复，以及每个相关会话在日界线前最后一条用户消息开始的完整上下文。用户与助手可能具有相同时间戳，顺序以原始消息 `rowid` 保持，不按随机 ID 排序。

`messages` 是保留的原始消息；`message_archive` 是具有外键的触发器投影。Checkpoint 缩小模型原文窗口，不会删除这些消息。因此历史日期仍可从原始消息读取；缺少或重建同文档案不会误判来源改变，真实档案冲突会影响来源 hash。

历史状态只取 `conversation.world_effects_committed` 中已提交的 `before/after`，按来源用户消息关联；不把 shadow、提议或 `wouldApply` 当实际变化。角色仍只有一个持久关系数值 `closeness`，即时情绪与社交容量独立存在。日记使用当轮历史好感度与状态，不能拿生成时的当前状态冒充过去；低好感也不能直接推导出厌恶。

没有对应回合感受记录时，日记允许写现在回顾时的主观印象，不允许补造“当时一直暗中讨厌”等确定的过去隐秘反应。用户转述、计划、否定、取消和更正必须保留归属与时态；角色人格中的公开／私人行为模式是条件性倾向，不是已经发生的共同经历。

正常生成需要两次逻辑调用：生成、审稿。唯一一次修复用完时最多四次：生成、审稿、修复、再审稿；格式或引用错误可能在审稿前被拒绝。所有调用的 `maxRetries` 为 `0`。审稿自身的网络或格式失败直接终止，不默认通过，也不会触发无界重生成。

## 存储与接口

迁移 `036_memory_diaries.sql` 创建三张表；现有迁移加载器自动发现该文件，无独立注册清单。

| 表                      | 保存内容                                                                                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| `diary_entries`         | 日记身份、角色、本地日期、固定时区与当前 revision；`agent_id + entry_date` 唯一。                                                                 |
| `diary_revisions`       | 每次成功的标题、正文、结构化草稿、冻结来源与 hash、生成元数据；旧版本保留。元数据包含提示词／审稿版本、角色版本和 hash、模型与 provider/profile。 |
| `diary_generation_runs` | 请求幂等 key、请求 hash、目标 revision、pending/succeeded/failed 状态、结果 revision 和失败代码；同一篇日记只允许一个 pending 请求。              |

| API                                                   | 行为                                                                                                                                      |
| ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /api/diaries/volumes?agentId=&year=&month=`      | 返回 `{ volumes }`。角色可选，年份和 1–12 月份在服务端校验。                                                                              |
| `GET /api/agents/:agentId/diaries?month=YYYY-MM`      | 返回 `{ entries }`，按角色读取，可限定月份。                                                                                              |
| `POST /api/agents/:agentId/diaries`                   | 请求 `{ entryDate, timezone, clientRequestId, expectedRevision? }`，返回 `{ entry }`。新建可省略 expectedRevision；更新必须携带当前版本。 |
| `GET /api/agents/:agentId/diaries/:entryDate/sources` | 返回条目 ID、revision、有效性与当前仍存在的来源消息，不从冻结快照重新暴露已删除内容。                                                     |

共享契约位于 `packages/contracts/src/diary.ts`。`DiaryEntry.body` 是用空行分隔的字符串；模型内部使用带 `sourceMessageIds` 的段落。条目包含 `validity: current | source_changed` 和 `hasNewMaterial`。四个 API 均使用 `Cache-Control: no-store`。

## 一致性边界

- 同一角色下，`clientRequestId` 与请求内容绑定；同一请求重放返回原成功 revision，即使以后已经生成更新版本。复用该 ID 提交不同内容返回冲突；失败请求不会重新调用模型，主动重试需新请求 ID。前端对结果不明的网络失败保留原请求 ID。
- 同日并发生成由 pending 唯一索引排斥，单进程的相同请求合并等待。超过 15 分钟的 pending 在新请求尝试时可标为中断；原运行随后不能再提交。此处采用版本与来源围栏，不持有聊天事务等待模型完成。
- 生成结束时重新收集资料，检查内容、删除、新回复、感受记录与角色版本，任何变化都拒绝旧结果。提交采用 expectedRevision 比较并在一个事务内写入版本和请求结果。
- 读取时比较每条旧依赖，而不是只比较数量。旧来源缺失或 hash 改变标为 `source_changed`；纯新增材料单独标为 `hasNewMaterial`。关联记忆变为 `needs_review` 或 `superseded` 也会影响来源状态，即使原文未删除。
- 日记不会回写 `memories`、更改运行状态或扣增好感；生成的文学叙述不会成为新的原始事实证据。语义审稿是有边界的模型质量检查，不是事实正确性的数学证明。

## 当前限制与维护验证

- 由用户手动触发，没有午夜定时写日记、后台自动补写或日记全文／向量检索。
- 单次完整材料最多 400 条消息、序列化字符串长度最多 120,000；包括必要上下文，超过上限明确返回错误，未静默截断。这里是 JavaScript 字符串长度，不是 token 或字节数。
- 没有当天用户分享、日期不存在、未来日期、版本冲突、来源变化、provider 失败或审稿失败均返回明确错误，不生成备用正文。
- 历史日期如果缺少当轮感受或状态记录，不能恢复当时未记录的具体心理活动。
- Fixture provider 只用于可重复的流程和数据边界测试；其确定性日记和审稿通过结果不代表真实模型的写作品质或语义可靠性。

后端接线为 `new DiaryService(store, clock, llm)` 与 `registerDiaryRoutes(app, diaries)`。主要测试是 `apps/server/src/services/diary-service.integration.test.ts`，覆盖真实 fixture 调用、日期／DST、角色隔离、同时间顺序、历史状态、感受依赖、幂等／并发、来源改删、旧版本保留、有限修复及 HTTP。互动感受和审稿模块有各自的定向测试；前端分页和动作门控测试位于 `components/memory-library/`。
