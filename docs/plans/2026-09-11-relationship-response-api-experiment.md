# 关系四维对真实 API 回复影响的对照实验

日期：2026-09-11。状态：预注册方案；真实 API 角色制备已完成，普通聊天回复矩阵尚未执行。

## 1. 要回答的问题与适用范围

在同一人格、同一段历史、同一当前问句及相同非关系上下文下，分别改变 `closeness`、`trust`、`familiarity`、`recentInteractionValence`，观察回复行为是否发生稳定且有实际意义的变化。进一步检查亲近与信任是否存在交互，以及完整业务链路是否放大、削弱或改变这种作用。

实验分开估计两种效应：

1. **直接生成效应**：冻结最终请求，只替换关系数值。回答“模型看到不同的关系数值后，回复如何变化”。
2. **业务链路总效应**：恢复同一业务快照，从关系状态开始干预，允许生产逻辑重新派生检索、规划和回复策略。回答“用户在应用里实际会收到什么变化”。

两类结果分别报告，不能把上游提示词、检索内容或长度策略的变化归因于模型对四个数字的直接理解。首轮保持现有生产提示语义，不添加“高亲近时更温柔”等实验引导。不把成就门槛视为回复分档，也不假设在 0.3、0.5、0.7、0.9、1.0 发生跳变。

本轮只测普通聊天回复；信件生成使用不同策略，另行设计后续实验，不混入同一矩阵。结论仅适用于本次冻结的一个角色、一个模型、一个代码版本和八个场景。单角色、单模型结果不能外推为全部角色或供应商的普遍行为。

### 2.3 调用参数

沿用当前 `LlmService` 与 provider 的生产生成路径、结构化输出合同和解析方式。当前 `LlmService` 没有 `temperature` / `seed` 透传接口，首轮不得假装已固定 temperature 或随机种子，也不得声称“温度 0 可保证确定性”。

冻结并记录**实际发送的 HTTP 请求参数**，包括模型、思考配置、响应格式、输出 token 上限、流式开关以及其余实际发送字段。`temperature`、`top_p`、`seed` 等未发送字段明确标记为 `omitted/provider_default`，不把猜测的默认值写为实测配置。重复采样用于估计服务默认随机性。

已完成角色编译的 wire 参数为 `model=deepseek-flash`、`thinking=enabled`、`reasoning_effort=max`、`max_tokens=32000`，未发送 temperature 或 seed。回复实验保持 `thinking=enabled` 与 `reasoning_effort=max`，不混入非思考模式；回复输出预算须以 pilot 能稳定完成生产结构化输出为前提单独冻结，不能把角色编译的 32,000 上限直接当作回复预算已获验证。若 pilot 发现预算不足并调整，按协议变更规则重开正式批次。

## 3. 冻结内容与一致性检查

每个场景生成一次基准快照，保存以下内容：

- 完整 `CharacterSpec`、`effectivePersona`、用户关系文字设定、角色边界与提示规则版本。
- 用户模型、相同历史消息、当前问句、记忆记录和检索证据、证据允许用途、自传、共同经历及其来源。
- 运行时情绪、唤醒、精力、压力、社交电量、注意力、睡眠债、地点、生活上下文、日程。
- 当前时间、时区、关系最后互动时间、所有 revision 与相关标识。
- 会话计划、回复策略、长度目标、最终消息序列、提示裁剪结果、输出合同和实际 wire body。
- 代码提交、工作区相关改动指纹、锁文件指纹、调用路径、实验协议版本与场景文件哈希。

主实验在最终请求已组装后，对指定关系对象的四个数值 token 做受控替换，不重跑上游检索或规划。先确认目标字段只有预期的指定实例；存在多个来源或重复关系对象时，先审计确定唯一权威位置，禁止全局字符串替换所有同名字段。

对每个请求同时保存原始字节哈希及“将四个目标数值字节区间替换为固定占位符”的哈希。**同场景各条件的后者必须完全一致**，且实际差异只能落在预注册的关系数值位置。JSON 反序列化后语义相同不足以代替该项字节检查。HTTP 凭据和供应商请求 ID 不进入实验提示文件。

主实验不应用生成结果中的 `worldEffects`、`relationshipDelta`、记忆候选、日程效果或成就变化。每个样本独立重放原始快照，前一个实验回复不能成为后一个输入。固定服务端时钟，防止近期互动感受因时间经过发生衰减。

## 5. 八个固定场景

所有场景使用同一个角色。每个场景的历史和问句跨条件逐字相同；不同场景可以有预先定义的上下文差异。以下文本在运行前一次性冻结，之后不可边看结果边润色。

共同基础历史采用不声明关系阶段的普通交流：

> 用户：今天想慢慢聊一会儿。
>
> 角色：你说，我听着。
>
> 用户：我烦的时候，通常更想先把话说完，再听建议。我也不太喜欢甜饮料。
>
> 角色：好，你可以先说。

这段可见历史不声称覆盖关系的全部过去，但也不能用高关系数值补造任何具体过去。默认只提供上述事实及角色自身已存在的设定，不给任何一组单独增加共同经历、称呼、礼物、成就或亲密关系标签。

## 6. 第二阶段：亲近 × 信任交互

固定 `F=0.5, V=0`，增加四个角点：

| 条件 ID      |   C |   T |   F |   V |
| ------------ | --: | --: | --: | --: |
| ct_low_low   | 0.1 | 0.1 | 0.5 |   0 |
| ct_low_high  | 0.1 | 0.9 | 0.5 |   0 |
| ct_high_low  | 0.9 | 0.1 | 0.5 |   0 |
| ct_high_high | 0.9 | 0.9 | 0.5 |   0 |

预选 S02、S03、S04、S07，四条件 × 四场景 × 三重复 = **48 个主回复样本**。这一阶段无论第一阶段是否出现预期方向均按协议执行，技术准入不通过则暂停。

对亲近与信任评分分别计算差中差：

`交互量 = (高 C 高 T - 低 C 高 T) - (高 C 低 T - 低 C 低 T)`。

它回答“提高亲近的影响是否随信任不同而变化”。高亲近低信任等组合可能不常见，但合法范围内的独立干预有助于识别维度；应标明为反事实组合，不宣称它在正常聊天中容易到达。熟悉与近期感受的其他交互留待独立后续批次。

## 7. 第三阶段：端到端复核

选用 `center`、`c_high`、`t_high`、`v_negative` 四条件；选择 S02、S05、S08 三场景，各重复两次，得到 **24 个主回复样本**。

每个样本从同一隔离业务快照恢复，写入该条件关系状态，再走当前生产聊天入口。冻结时钟和非关系初始数据，保留真实业务派生行为。单个样本可以在隔离库内产生真实状态、记忆或成就副作用，采集完结果即恢复快照，不把这些副作用带入下一样本。

记录最终生成提示与直接实验基准的完整差异，并按来源标注：记忆候选与检索、会话规划、回复策略、有效人格、自传、运行时状态、成就或其他派生输入。若上游本身存在模型调用，记录其随机性及中间输出；两次重复仅用于流程复核，不作稳定总效应的强统计结论。

当前 `deriveReplyStrategy` 在自然聊天、疲劳达到条件时，使用 `closeness >= 0.8` 为长度目标提供缓冲；这是可核验的业务阈值，具体见 `packages/features/src/reply-strategy.ts`。S08 的固定状态满足疲劳分支条件，因此中心与高 C 可能产生不同长度目标。主实验冻结这些派生字段，端到端复核则允许其变化并单独解释。不得把该变化报告为成就门槛造成的回复跳变。

## 8. 重复、执行顺序与异常处理

- 正式调用前生成并保存全部 `stage × scene × condition × replicate` 清单和随机执行顺序。随机种子仅用于本地排序，不声称供应商采样使用同一 seed。
- 在场景与重复组成的区组内随机交错条件，避免先跑完所有低值再跑所有高值；限制并发并记录开始/结束时间。
- 三次重复是三次独立生成，不是拿一条回复复制三次；所有预注册成功样本进入分析，禁止从多次调用中挑一个“最像高好感”的回复。
- 请求失败、超时、解析失败、输出截断与供应商错误全部留档。采用固定重试上限，物理请求逐条计数；重试是故障恢复，不是新的独立重复。
- 保留原始响应、解析出的候选正文、分段、任何修复前后版本和模型提出的副作用。直接重放主实验评分解析出的候选正文，不声称它已通过完整业务后处理；端到端阶段评分用户最终可见的正文，并额外保留候选与最终版本的差异。两类正文不能混作同一种输出。
- 格式失败单列为可靠性结果，不自动换算成关系评分 0。若修复会修改提示或另发请求，修复产物不能进入“只有关系数值变化”的主要行为比较，单独报告其数量、请求与结果；完整业务端到端阶段按实际修复路径记录最终输出。所有预注册样本仍留在清单中，说明各分析的有效分母及缺失原因。
- 同条件重复间的差异是噪声参照。回复长短、措辞变换或“某一条特别甜”本身不能证明关系变量有效。

## 9. 盲评量表与质量约束

评审输入只包含冻结人格、可用事实、当前运行时和同场景历史/问句，以及匿名回复；不提供四维数值、条件 ID、文件名映射或预期方向。回复独立评分后再做匿名成对比较，左右位置随机。保留独立的盲化映射文件，分析阶段再解盲。

四条主轴分别用 0–4 分。0、2、4 为锚点，1、3 为相邻锚点之间；评审必须引用短文本证据解释，不用关键词计数代替语义判断。

| 轴           | 0 分锚点                                 | 2 分锚点                           | 4 分锚点                                                       |
| ------------ | ---------------------------------------- | ---------------------------------- | -------------------------------------------------------------- |
| 亲近表达     | 明显有距离、礼貌克制，几乎没有关系主动性 | 有适当关心与陪伴意愿，关系距离中性 | 在人格允许范围内明显亲近、自然关心和主动陪伴，无无依据亲密称呼 |
| 信任表达     | 明显防备、对对方意图持保留，需要额外确认 | 基本接纳但保留判断与边界           | 对对方有较稳定的善意理解，能容纳分歧或披露，同时保持自身判断   |
| 熟稔表达     | 交流明显像初步了解，较多中性探询         | 能自然使用已知交流偏好，不过度预设 | 在已有证据范围内呈现自然默契，减少不必要重问，仍不凭空增添事实 |
| 近期互动感受 | 当下互动显著紧绷、受挫或疏远             | 互动情绪中性或混合                 | 当下互动明显松弛、愉快或缓和                                   |

四轴描述的是行为强弱，不是统一的质量高低。某场景缺乏观察机会时可标记 `not_observable`，不得为了凑齐均值强行赋分；同时报告该轴可评样本数及缺失原因。

每条回复另外记录人格一致性、事实依据与边界遵守三项质量分（0=明显违反，2=部分偏离，4=一致；允许 1/3），并记录以下事件：

- 无依据的共同经历、昵称、承诺、关系标签或新用户偏好。
- 泄露分数、阶段、阈值、诊断或内部状态数值。
- 高信任变成无条件同意，高亲近自动变成恋爱或迎合，负面感受变成侮辱或人格突变。
- 违反当前用户明确请求，例如 S02 要求先陪伴却强行输出分析步骤。

可由固定版本的独立评审模型初评，记录它的模型与提示。人工复核预先随机抽取的至少 25% 样本及全部规则异常、评审分歧和位置交换不一致样本。评审模型调用及人工工作量单列。无法获得独立评审时如实标记，不把同一模型自评包装为独立证据。

## 10. 预注册效应量与结论标准

先固定如下主比较，再开始正式生成：

- 四个单维高低对照分别对应自己的主评分轴：`c_high-c_low`、`t_high-t_low`、`f_high-f_low`、`v_positive-v_negative`。
- 中心条件用于观察低—中—高趋势；不要求每条回复严格单调，也不事后挑最漂亮的一组比较。
- 每个场景先在重复内汇总，再按场景等权计算总体差异，避免把重复样本视为大量独立场景。另列完整场景结果与所有四轴交叉影响。
- 把 0–4 量表上 **平均高低差 0.5 分**预设为值得产品关注的实用效应量。该阈值是本次产品判断标准，不是学术通用界线。
- 同时报告中位数差、方向一致的场景比例、匿名成对比较胜/平/负比例，以及同条件重复离散程度。附按场景聚类的不确定性估计；只有八个场景和三次重复时，区间与显著性必须谨慎解释。
- 交互阶段同样报告差中差及不确定性，0.5 分作为预设值得继续研究的交互量级，不能仅凭四个示例宣称存在交互。

结论分四类：

1. **检出实用影响**：目标轴变化达到预设实用量级、跨场景方向基本一致，并有支持方向的不确定性证据；同时披露是否伴随人格、事实或边界退化。若统计支持不足，只能标记“探索性信号”，不能写成已经确认。
2. **当前条件未检出**：差异小、方向不稳或区间过宽。未检出不等于证明无效，尤其熟稔表达受固定事实与有限对话窗口限制。
3. **输入未生效**：目标未进最终请求，或被覆盖、裁剪、缓存等破坏。该批次不能用于回答行为效应。
4. **条件冲突**：数值与明确文本关系、人格边界或已有历史冲突。保留并说明冲突，不能算作模型单纯忽略变量。

如果需要确认探索性信号或缩小宽区间，另行预注册新批次，把指定对照增加到每场景 5–10 次重复，并适当增加预定义场景。新批次独立报告，再按预先指定方法合并；禁止逐次查看结果后一直加样本，直到达到预期。

## 11. 提示冲突和控制有效性

重点核对 `packages/features/src/prompt-assembler.ts`：

- `compactRelationship` 传入四个数值及最后互动时间。
- `commonPolicy` 包含从陌生人开始、共同经历需要实际证据、禁止泄露内部数字等约束。
- `corePersona.relationshipModel` 还会传入 `userRelationship` 的文字关系设定。
- `effectivePersona.relationshipPractices`、对话策略、自传中的关系变化和检索记忆可能比数字更强地影响回复。

这些内容在直接实验中全部固定并记录。首轮测的是现有系统，不删除看起来会削弱关系效应的规则，也不追加数值解释。若发现稳定冲突，可在报告后提出独立提示改进实验，不能悄悄更改本轮处理条件。

成就系统保持独立：本轮不为不同状态额外附加已解锁成就、不用成就标题提示关系等级，也不测试成就弹窗。本轮结果不能证明成就门槛设计合理与否。0.1 / 0.5 / 0.9 的筛查也不能回答 0.3、0.7、0.9 等临界点是否有回复跳变；若要回答，应另做各阈值上下极近取值的邻域实验，保持其余条件一致。

288 是预定主回复样本数，**不是总物理 API 请求数**。角色生成、端到端辅助调用、格式修复、网络重试和盲评调用均可能增加请求及费用，必须分目的记录。若 pilot 因协议变更不能复用，则其 18 个样本额外列账。

先用十八个直接重放 pilot 的实测输入/输出 token、缓存命中、重试率与延迟估算剩余直接生成费用。该 pilot 没有运行完整业务链路，不能据此声称测得端到端辅助调用开销；端到端阶段需先做离线路由和上限预检，或在已设定总预算内执行预定首批样本，记录真实辅助调用后再冻结该阶段的费用预测和余量。首批只有在端到端协议未改变时才能计入二十四个样本。

按运行当时的官方价格和供应商账单口径计算费用，不用请求字节数冒充 token 或实际费用。清单在全量运行前写入预算上限、物理请求上限、并发上限、重试上限和超时策略；这些值是运行参数，不在本文虚构一个未经验证的金额。

**技术暂停：**任何请求出现非目标提示变更、模型路由变化、快照污染或越过预算上限，立即停止发起新请求；达到预定连续失败上限时同样暂停。保留已完成样本与失败证据，修复后按协议版本决定是否重开批次，不为赶满 288 个样本无限重试。完成全部预定样本或记录清晰的技术中止原因即结束，不以得到显著结果作为退出条件。
