# 单一好感度控制亲和表达与回复篇幅：可行性研究

研究日期：2026-09-11。状态：代码审计和离线策略测算已完成；生产实现、数据迁移与新策略真实API验证尚未执行。

## 结论与建议

建议将现有四轴收敛为一个长期好感度，并让它明确影响日常对话的亲和表达与展开程度。内部沿用 `relationship.closeness` 的0–1取值，产品文案可显示为0–100好感度。现有值、成就进度和历史证据保持原样。

能否有效取决于整条控制链：**唯一好感度 → 服务器计算当轮表达策略 → 模型按策略组织正文 → 检查最终交付 → 按实际表现验收**。仅删除三个数字，仍让模型自行理解剩下的数字，不能解决上一轮发现的问题。

一个变量足以表达当前产品所需的“愿意与这个人投入多少日常交流”。代价是放弃独立模拟“熟悉但不信任”“信任但不亲近”等二维关系状态；如果产品暂时不依赖这些状态，这是合理的简化。人格中的谨慎、信任判断、独立意见以及真实共同经历仍由人格、上下文和记忆承载。

## 1. 当前代码为什么难以产生分层

## 2. 一个值应控制什么

唯一持久化关系状态：`closeness`。可以把它对用户称为“好感度”，对实现解释为长期关系中的交流投入程度。

服务器由这个值派生当轮目标字数、允许展开程度、主动承接方式及亲和指导。派生策略不单独存储为成长数值，不让模型更新，也不作为另一套成就进度。无需另建可以独立积累的“亲和度”“熟悉度”来替代旧四轴。

| 好感度 | 普通闲聊的表达倾向                             | 以程知夏为例的候选目标 |
| -----: | ---------------------------------------------- | ---------------------: |
|     10 | 简短自然，回应当前内容；礼貌有距离，少主动展开 |                 约26字 |
|     30 | 稍放松，回应后可补一小句或一个相关问题         |                 约42字 |
|     50 | 更愿意接住情绪或话题，适量表达自己的看法       |                 约67字 |
|     70 | 更自然地表达关切，沿同一话题多说一层           |                 约91字 |
|     90 | 更愿意交流和分享态度，在真实证据内表现熟稔     |                约107字 |

这是候选政策，不是新API实测的回复长度，也不是所有角色共用的固定字数。少言角色的高档仍可比健谈角色短；温柔角色的低档仍然温和。各档标签用于解释，实际数值连续变化。

测算使用一个平滑单调的候选公式：

```text
A = clamp(closeness, 0, 1)
S = 3A² − 2A³
B = clamp(averageMessageLength × (0.7 + 0.9 × verbosity), 40, 120)
普通闲聊目标 T = round(B × (0.5 + 1.8 × S))
```

101个输入点的目标已确认单调非下降。系数和限幅仍需真实API校准；这里只证明服务器可以稳定生成有区别的策略，不证明模型已经遵从。子审计里的其他公式属于备选例子，本研究主方案以本节曲线作为后续校准起点。

### 亲和表达需要具体指令

低好感可指示：回应当前一件事，用简短完整的表达，维持人格原有礼貌，不主动开多个话题。高好感可指示：沿当前话题自然多承接一层，愿意表达个人态度或具体关切，避免套话和重复安慰。不能只告诉模型“更亲切一点”，也不能靠多加语气词、昵称或重复“我在”获得高分。

表达示意，以下由研究者撰写，非新的模型调用结果：

> 用户：这周忙得挺累的，今天终于能歇一下。

- 低档：辛苦了，今天就好好歇一歇。
- 高档：总算能松一口气了。今天先别急着把休息也排成任务，想到哪儿歇到哪儿就行。你要是想吐槽这周的事，我听着；不想再提工作，我们就换个轻松的话题。

两者保持同一人格，变化在交流投入。高好感并不自动建立恋爱关系，不凭空生成往事，也不要求角色同意用户的观点。

## 3. 篇幅控制的优先级

好感度控制**日常对话默认展开程度**。应明确以下规则：

1. 用户明确只要一句、只说结论、不想分析、希望安静陪伴时，按当前请求收短。高好感可以让短句更自然体贴，无须变成长文。
2. 用户明确需要详细解释或完整内容时，把问题回答完整；低好感减少客套和额外延伸，不省略必要内容。
3. 纯问候、晚安、收到等回合有独立的小预算，不随好感线性膨胀。
4. 其他普通闲聊按好感度派生目标，再叠加精力、疲劳、社交容量等当下状态的调整。高好感不抹掉疲劳。
5. 人格的价值观、语言习惯、知识边界和作者明确硬规则保留。需要在提示中说明：作者平均字数和verbosity是基准，当轮篇幅由服务器策略在上述优先级下计算。

不设置必须补足的字数下限。一个完整、自然的短回答无需为了高好感凑到目标值。“熟悉后更愿意多说”应该体现在多次可展开场景的分布，而不是每句逐字强制增长。

## 4. 怎样让效果可测、可控制

### 输入阶段

- `deriveReplyStrategy` 统一计算当轮表达策略，普通闲聊绕开原先80字下限，避免新公式又被旧限幅覆盖。
- 当前关系提示只提供唯一当前值及派生策略。初始好感度仅用于初始化，初次陌生文字标明是起点，不作为永久关系现状反复下发。
- 只允许模型提议单值关系变化，并提供证据；候选正文的亲和度不反过来自动给自己加分。
- 主生成与所有后续修复使用同一份策略版本及同一当前好感值。

### 输出阶段

记录最终用户可见的整回合正文长度、句数、气泡数、目标、越界情况、修复次数与结果。主长度指标统一为NFC规范化后的可见正文Unicode码点数，包含标点、排除空白；同时保留原文及含空白码点数供复核。分成多个气泡不能绕开整回合统计；推理内容和JSON字段不计入正文长度。

建议首版对普通闲聊的**严重超长**做最多一次样式重写，并纳入同一回合总调用预算；格式和事实修复优先，预算不足时不额外追加样式请求。现有 `repairBudget.remaining=1` 不是全链路总预算，最终goal review还有独立的评审/重写调用，实施时需要新增统一预算协调或明确计算全链路上限，不能把当前局部预算直接当成全局保证。候选可从 `max(ceil(1.6T), T+16)` 作为超长复核线开始校准。参考下限不用于失败判定。

建议把样式重写放在最终goal review之前，仅修改候选可见正文和相应气泡，保留 `finalized.world` 的非reply内容，不重跑 `worldEffects.resolve`。必须继承 [conversation-service.ts:729](E:/2026/ChatPLUS/apps/server/src/services/conversation-service.ts:729) 的 `allowRewrite` 豁免：显式事实回复、consent权限展示、enforced日程权威展示不进入样式重写，不能只依赖普通inspect去恢复专用权威文本。

选定文本后重新执行现有事实、语义及输出守卫，并进入原有 [conversation-service.ts:701](E:/2026/ChatPLUS/apps/server/src/services/conversation-service.ts:701) 最终目标复核；历史、关系增长、记忆和活动仍在原有事务中只提交一次。最终goal review若再次改写正文，需要重新记录实际交付长度，不追加无限样式修复。若实现选择在goal review之后修改正文，则原 `goalAchieved`、语义审计和 `finalTextSha256` 必须失效并同步重评/重建，不能保留旧正文的通过状态。

不截取前N个字，也不按标点机械截前几句。若重写仍不合格，首版建议保留语义完整的有效回复并记为样式未命中，优先可用性；因此承诺的是可验证的分布差异。若未来要求每次都满足严格上限，就必须接受拒绝交付或明确失败的代价。

不能用 `max_tokens=30` 实现“30个中文字”。它限制的是整个completion；当前请求还要承载结构化输出与推理。DeepSeek官方明确说明达到token限制可能导致JSON被截断。当前主聊天实际预算还被 [chat-output-budget.ts:9](E:/2026/ChatPLUS/apps/server/src/services/chat-output-budget.ts:9) 托到24,576，不能只改策略中的小预算就声称真实请求已限长。[DeepSeek Chat Completions文档](https://api-docs.deepseek.com/api/create-chat-completion/)

## 5. 合并后如何增长

建议定义为有上限的长期积累：**合格互动基础积累 + 有证据的关系事件影响**，再经过档位能力、每日预算、状态边界和事务幂等检查。

- 现有familiarity每轮 `+0.001` 可作为基础增长的首个校准候选，但不能机械搬过去。重复请求、重复刷屏、失败fallback、明确破裂/越界或尚未成立的修复不领取正向基础增长。
- 普通意见不同、用户暂时不想聊、角色疲劳不应自动永久扣好感。短时感受交由现有moodValence、energy、stress及当前上下文表达，不将recentInteractionValence的48小时衰减合并为长期关系衰减。
- 真正影响关系的支持、守约、伤害、修复由证据和服务端政策决定，模型只能提议，不能直接定最终值。
- 初版可从现有量级校准：基础增量候选0.001，基础日预算候选不超过原familiarity的0.012，总关系日增长受现有closeness的0.04预算约束。它们是节奏候选，不是已经决定的新规则；capabilityScale及合格互动筛选会继续影响实际速度。
- 现有聊天日预算使用带符号净变化/方向额度，旧共同活动路径使用绝对预算。应选定并统一语义，不能误把二者当成同一种上限。升级当天延续旧closeness预算，不能重置后再领一份。
- 保留原有请求幂等、revision/CAS和事务保护；同一回合重试/重写不重复增长。日使用记录是防刷元数据，不是第二个好感度。
- 保持长期好感有限步可到1.0。若用 `Δ×(1−A)` 渐近衰减，可能永远达不到现有满级成就；采用有限步封顶或明确到顶政策。

现有off/shadow仅提交基础积累、enforced才实际应用模型关系提议；轻量档capabilityScale=0。本次建议先保留既有档位权限，不把压缩字段顺手扩展成所有档位的新权限。若产品希望轻量角色也可培养好感，应作为明确的能力规则变更另行纳入。

详细链路见[增长与验证审计](E:/2026/ChatPLUS/artifacts/single-affinity-feasibility-20260911/growth-validation-audit.md)。

## 7. 实施顺序与验收

建议以一个协调版本完成以下工作，可拆提交但避免服务端/前端/Schema处于互不兼容的半升级状态：

1. 定义新单值合约和旧数据读取适配；沿用closeness，不新增双写affinity。
2. 实现单值派生回复策略、当前关系提示优先级和生成/修复共用策略。同步处理信件的真实依赖。
3. 实现合格基础增长、单值长期事件及日预算投影，保留幂等和能力策略。
4. 在快照备份和迁移事务中清理当前状态的退役字段，保留历史、旧成就和当天预算；补齐归档读取兼容。
5. 完成离线检查，再用冻结角色与场景运行真实API对照，根据客观长度、亲和度、质量和修复开销决定是否启用。

### 必要的离线检查

- 0–1范围内策略单调；角色基准、问候、明确简短/详细、安静陪伴、疲劳优先级正确；最终字数按整个可见回合统计。
- 当前请求只有一个权威关系值；初始数值不再次竞争；修复沿用同一策略；无越界能力或重复世界效果提交。
- 重试、失败、重复刷屏、越界、修复、普通分歧、跨日、能力关闭/轻量档及到1.0行为符合政策。
- 旧runtime、旧角色、trust-only里程碑、冻结信件、旧成就和旧日预算可读；迁移不凭空解锁，不重复累加。

### 建议真实API验证：144个直接样本 + 24个完整流程样本

固定程知夏、DeepSeek实际路由、各场景相同历史与非关系状态，先用旧系统/新单轴策略 × 好感0.1/0.5/0.9 × 8场景 × 3重复，共144条。旧系统其余关系轴固定。最初12条可作为技术准入，协议不变才纳入总数。

四个可展开场景：日常闲聊、分享一天的小事、已知偏好衔接、温和分歧。四个例外：明确只说一句、明确详细说明、要求安静陪伴、角色疲劳。完整流程复核选4场景 × 3档 × 2重复，共24条。168是主样本数，格式修复和样式重写额外计物理请求及费用。

这组对照检验整套新方案，不能把差异单独归因于“删除三个字段”。若要分离简化字段与明确策略的贡献，后续另加“单值裸数字、不带派生策略”的消融组。

候选验收线需在调用前冻结：

- 可展开场景：高/低平均正文长度比至少1.5，绝对多至少15字，至少3/4场景低≤中≤高；这是首轮筛查线。若产品要求更鲜明的体验，可在测试前提高至1.8倍及25字，不能看到结果后移动门槛。
- 长度建议区间命中率至少80%；超长复核线、初次命中、修复后命中分开统计。不强制补齐下界，较短但完整的回复不因好感高而判失败；报告需同时列上界遵从率与参考区间分布。
- 明确简短/详细等例外的请求遵从至少95%，并逐条检查内容充分性、重复凑字、人格、事实与边界。不能用输出更长替代亲和度和质量证据。
- 两位评分者分别评同一完整48组低高配对，左右平衡随机、条件隐藏；先用测试外12例校准亲和度、冗余和边界标尺。两位都覆盖全部条件，避免上一轮条件与评分者混杂。
- 亲和度的候选关注线为平均高低差至少0.5/4、配对高档获胜至少70%。以新策略4个可展开场景×3重复的12组配对作初筛分母，旧策略对应12组作为基线；平局保留在分母并单独报告。两位评分者是同一回复的复评，不能把12组计成24个独立样本。例外场景不要求更长或明显更亲密，作为遵从性对照单列。分歧须保留，两位方向相反则不能宣布确认。
- 所有失败留在完成率分母，修复成功单列，不为获得理想结果替换样本。AI评分明确标记为AI；通过后还需其他人格和人工体验检查才能外推产品整体。
