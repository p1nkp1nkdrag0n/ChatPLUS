# 单一好感度实施记录

日期：2026-09-11。用户批准将好感度压缩为一个变量，主要控制日常对话亲和表达与展开程度，并明确现有数据全部为可清理测试数据。

## 数据模型

唯一成长值沿用 `relationship.closeness`，范围 0–1。`userId` 和 `lastInteractionAtUtc` 是关联与时间元数据。角色初始参数只保留 `initialCloseness`，新建角色统一从 0.1 开始。状态、增量和角色合约严格拒绝退役字段，三个 runtime 写入口在入库前校验。

当前聊天提示只下发当前 closeness 和服务器派生的表达策略；初始关系描述标明为起点，不构成永久陌生状态。信件策略和记忆检索诊断也改用 closeness。检索排序未因诊断指标变化而修改。

关系成就仍读取 closeness 和原有阈值，没有新增独立成长值。数据库回归测试覆盖五档跨阈值解锁及重复更新不重复解锁。

未增加历史兼容读取层或破坏性自动迁移。当前 `.env` 指定的本地实例 `data/personasim.db` 已重建，角色、会话、运行状态和成就进度清零；两个 API 提供商、默认模型配置、密钥元数据及密钥文件保留，配置内容逐表核对一致。重置操作仅针对该本地实例；旧研究文件和其他独立实验库不受影响。新程序不支持直接加载旧四轴业务记录。

## 对话行为

普通闲聊目标使用连续曲线：

```text
A = clamp(closeness, 0, 1)
S = 3A² − 2A³
B = clamp(averageMessageLength × (0.7 + 0.9 × verbosity), 40, 120)
T = round(B × (0.5 + 1.8 × S))
```

以原实验角色程知夏的平均篇幅 45、verbosity 0.4 为例，好感 10 / 30 / 50 / 70 / 90 的普通目标为 26 / 42 / 67 / 91 / 107 字。目标还受疲劳、注意力等当前状态影响。这些是服务器目标，实际模型回复需单独测量。

低好感强调礼貌距离、完整回应一件事、少主动延伸；高好感允许沿同一话题多承接一层，表达有根据的个人态度和关切。人格、价值观、事实边界和原有语言习惯持续有效。高好感不自动推导恋爱、同意、授权或共同经历。

用户明确要求一句话、问候、安静陪伴时保持简短；详细问题完整回答。明确短要求优先于同时出现的“完整方案”等深度关键词。没有必须补足的字数下限，也不机械截断有效正文。

普通闲聊超过 `max(ceil(1.6T), T+16)` 时，允许最多一次样式重写。已有质量修复优先，显式事实、权限和日程权威展示豁免。样式重写只替换正文及气泡，不重新计算世界效果，最终目标复核之后刷新实际正文统计和哈希，再通过原事务提交一次。重写失败或仍然超长时保留原有效正文并记录未命中。若最终语义守卫把回复改为失败兜底，提交前纯重算关系投影，撤掉先前计算的基础奖励及对应日额度；已经验证并实际应用的事件贡献保持冻结，不借释放预算追加奖励。

前台对话的判断、生成及修复链路共用 12 次逻辑调用上限；样式重写禁用供应商重试，并为最终目标复核预留最多 3 次逻辑调用。后台生活/日程结算仍使用原有独立服务，这个计数不涵盖其调用，也不是 HTTP 请求或计费 token 上限。最终 `assistantMessage.metadata.affinityDelivery` 保存目标、实际篇幅、例外、重写结果、调用计数和最终正文哈希。

生产篇幅计数口径为 `non_whitespace_graphemes_v1`：整回合正文的非空白可见字素，包含标点，排除 JSON 与推理内容。与研究候选的 NFC 码点口径有细微区别，例如组合 emoji；验收同时报告两者。气泡拆分不能绕开整回合计数。

如果输入预算无法容纳必需的当轮策略，返回 `required_segments_exceed_budget`，不静默截掉表达控制。正常预算仍支持上下文压缩。

## 增长与成就

合格互动基础增量为 `0.001 × capabilityScale`，基础奖励当地日累计上限 0.012；基础奖励之间至少间隔 60 秒。空内容、纯重复字符、当天跨会话标准化后相同内容、真正失败兜底、明确关系破裂或显式修复不领取基础奖励。

模型只能提议单 closeness 变化，服务端验证证据、能力档位、单次限额及日预算。普通分歧和短时疲劳不自动永久扣好感。轻量档不增长、日常档倍率 0.5、高拟真档倍率 1；off/shadow 只实际提交合格基础奖励，enforced 才实际应用模型提议。

聊天与共同活动共用当地日有符号净变动区间 [-0.04, +0.04]。基础奖励的累计额度独立记账，负事件与修复不退还该额度；账本是防刷元数据，没有第二个好感进度。预算从已提交审计重建，支持进程重启和当地日期切换。

共同活动完成 +0.006、部分完成 +0.003，不额外领取聊天基础奖励。缺少用户责任证据的自动跳过或取消不扣好感，避免角色自身疲劳或随机未赴约被算成对用户的永久扣分。聊天中的负提议需要明确指向关系的失信、伤害或破裂证据；身体伤痛、第三方事件和临时暂停不构成负好感准入。幂等、事务及 revision/CAS 保留，满级 1.0 可有限步达到。

- 最终完整测试：**310 文件、3,791 项全部通过**。覆盖严格单值写入、五档成就、跨日与重启账本、重复/失败/越界/修复、活动结算、真实 HTTP 提交、样式重写与最终目标复核后的正文一致性。
- `pnpm build` 全工作区构建通过（包括 TypeScript 校验与 Web 生产构建），`pnpm lint` 通过。最终源码经交叉审查后冻结；完整测试期间没有修改受版本管理的文件。
- 清理后的实际本地实例可成功启动，角色数 0、提供商配置 2，SQLite `integrity_check=ok`、外键错误 0。
- 真实 API：同一程知夏角色、每场景相同人格/上下文/非关系状态，DeepSeek `deepseek-flash`，72 direct +24 E2E 共 **96/96 技术成功**，96 次物理请求，合计 **839,583 token**。普通闲聊在好感 0.1 / 0.5 / 0.9 的平均篇幅为 **28.83 / 57.83 / 82.08**，4/4 普通场景均值逐档递增；短请求、详细请求、安静陪伴保持独立篇幅规则。
- 两位 AI 对相同 12 对普通场景进行隐藏条件复评，平均亲和差分别 +0.167/+0.667，高档获胜分别 2/12、8/12，**未达到预设亲和筛查线**。不能把长度分层等同于亲和度稳定提升；高档部分回复仍有多余自述。
- 保留质量失败：一条详细任务的分钟总数超出要求，一条 E2E 补写未证实的“方案第三版”。技术成功不代表事实和任务质量全部通过。
- 全部真实 E2E 都走正常一次生成，没有实际触发样式重写；超长重写、失败保留原文、预算和最终 fallback 撤奖励由最终代码的离线/HTTP 回归覆盖。真实 API 完成后的增长归属与最终 fallback 修正没有被倒称为已运行真实网络验证。
