## F1：明确求助被“先听我说”的字面出现覆盖（优先修复）

**定位**：`packages/features/src/conversation-context-plan.ts`，`LISTEN`、`ADVICE`、`buildConversationContextPlan()`；`packages/features/src/prompt-assembler.ts` 的 `replyStrategy` 消费分类结果。

原始输入：

```text
不用先听我说，直接给我建议。
不是让你先听我说，是请你帮我分析。
```

独立复现均得到：

```json
{"intent":"venting","adviceRequested":false,"supportStyle":"listen"}
```

原因是 LISTEN 命中被否定的短语，而 `adviceRequested = !listen && ADVICE.test(originalQuery)` 全局压制帮助请求。

**影响边界**：这是确定的规划错误；不声称真实 LLM 每次都会错误回复。原始用户消息和其他提示可能使模型自行纠正，但不能依赖模型抵消服务器的错误指令。

**修法**：先识别被否定、被引述或被修正的分句，再判断有效请求；当前有效请求优先于旧默认偏好。混合请求如“先让我说完，再分析”需要表达阶段顺序，不应二选一。无法判断时用中性提示，不输出强倾听规则。

**回归**：在现有 `conversation-context-plan.test.ts` 增加同义改写、否定范围、前后转折及引述场景；然后加 HTTP 测试验证最终 prompt 的 `adviceRequested` 与本轮意图一致。

## F2：检索候选话题被用于人格适应的生效判断（优先修复）

**定位**：`apps/server/src/services/conversation-service.ts` 中 `personaRuntime.snapshot({topicText: [input.text, ...contextPlan.expandedQueries].join("\n")})`；`packages/features/src/conversation-context-plan.ts`；`packages/features/src/conversation-topic.ts`；`packages/features/src/persona-projection.ts`。

前文：

```text
以后聊工作时，请先听我说，不要急着给建议。
换个话题，昨晚和妹妹看了一部电影。
```

当前输入：

```text
她说电影很好看，我也觉得挺有意思。
```

当前句没有工作话题。但“她”触发扩写，最近用户原文被放入 `expandedQueries`；旧工作句又进入 snapshot 的 `topicText`。独立复现：仅当前句与“工作”匹配为 false，拼接后为 true。

**后果**：若已接受的工作范围适应满足其余有效性条件，画像构建会把它选入当前电影话题。即使最终模型可能按 scope 自行忽略，投影已失去应有的范围筛选正确性。

**修法**：明确分离 `retrievalCandidates` 与 `resolvedCurrentTopic`。未消歧的候选只能帮助检索，不能使人格习惯生效。当前明确话题优先；仅在有证据确认连续指代时继承前文话题。不要通过简单删除所有前文来解决，否则真正的“她又那样了”无法延续。

**回归**：在同一个 session 中切换工作→家庭/电影，保留旧话题在最近三条中；检查 `effectivePersona.relationshipPractices`、最终 prompt、修复 prompt 均不带旧话题习惯。另设真正工作指代的正例。

## F3：直接问已有项目近况时可能整包丢弃生活上下文（优先修复）

**定位**：`packages/features/src/life-context-selection.ts`，`selectLifeContextForTurn()`；`conversation-context-plan.ts` 的 LIFE / intent。

设服务端已有 `ongoingThreads=[{title:"城市速写", ...}]`。用户问：

```text
城市速写画得怎么样了？
```

独立复现：`relevantTitle=true`，但 intent=casual、allowCharacterLifeMention=false、contextMessageIds=[]，最终 `selected=false`。

**修法**：将“明确询问匹配中的角色主线”单独识别为当前近况请求；允许选入对应主线及必要证据，而不是依赖“你最近”等固定措辞。对少量明确主线优先返回相关项；校验端继续保留完整因果快照。

**回归**：正例包括“城市速写画得怎么样了”“稿子后来怎样了”；反例包括“我看见别人有本城市速写”“先别聊你的项目”。不能把提到标题本身当成无条件授权整包生活信息。

## F4：一句话中的“现在”会使长期偏好的明确撤回失效（需要修复）

**定位**：`packages/features/src/persona-projection.ts`，`deriveExplicitPersonaPracticeRetractions()`。

```text
现在改一下，以后聊工作时可以直接给我建议。
```

函数在解析“以后”之前因 `/现在/` 命中提前返回 `[]`。这与“只是这一轮给我建议”的临时例外不是同一语义。

**影响边界**：其他记忆路径可能更新内容，因此不声称所有系统状态必定完全未变；但专门的适应撤回路径明确漏掉了该请求。

**修法**：区分请求发出的时间和新规则的适用时间。“现在改一下”修饰操作，“以后聊工作时”才修饰偏好范围。按分句和生效区间解析，而不是全句禁词。来源、范围和版本验证保留。

**回归**：对比“这次先给建议”“现在起，以后给建议”“以后还是先听，但今天可以分析”。验证下一轮、新 session、重启后的关系习惯；临时例外不撤回长期偏好。

## F5：现有长测不能直接承担本分支的完整验收（测量阻断项）

### 旧 v3 runner

- `companion-long-run-v3-runner.ts/buildLongRunV3ServerConfig()` 强制 `autobiographyMode:"off"`。
- manifest 的 featureFlags 没有冻结 `companionContextMode`、`personaRuntimeMode`；configSha256 也没有纳入这两项。
- CLI 只支持真实档案 `deepseek|bigmodel`，付费门为 `RUN_PAID_LONGRUN=1`。
- 108主干+6+6分支的旧120轮主要是决策因果回归，不能仅靠增大轮数变成新连续性验收。

### product-life runner

- 强制启用 memory/autobiography/correspondence，适合作为新 runner 的基础；42轮、D0到D45的旧场景仍不是新的完整覆盖。
- 两个新开关从 base config 继承，并未在 runner 内强制打开；外部必须设置并在启动时断言。
- `resumeIdentity` 未纳入两个新开关或 Git SHA/工作树指纹。按该代码，修改这两项后 resumeIdentity 可以保持相同，恢复检查无法据此阻止混用条件。
- CLI 固定 Qwen 用户档案、BigModel 角色档案；付费门为 `RUN_PAID_DUAL_MODEL=1`，不是 v3 的门。

**修法**：保留旧 runner 的历史回归语义；给新验收创建 versioned manifest，并冻结实际最终配置、Git SHA、代码差异、场景 hash、角色基线 hash、模型参数、两个新开关、retention 和所有参与策略版本。resume 必须比较这些字段。仅有 checkpoint 文件并不证明创建过“对话自传压缩 checkpoint”；两种 checkpoint 分开计数。

## 设计取舍，不应直接当成 bug

1. `validateEvidenceSemantics()` 目前只证明完整原文或服务端构造报告，其他抽象返回 insufficient。`preserveUnverifiedAutobiographySources()` 会把未证实概括降为归属原话报告。这样比词面重合放行更可靠，但不是已经实现语义理解，可能增加上下文体积、拒答和精确召回失败。真实评测必须同时检查正确回忆率和拒答率。
2. 自动适应只有两种，属于受控首版范围。无需为了通过测试仓促开放任意人格 patch；在报告里把“一致的倾听习惯”与“认识/信念成长”分开。
3. 当前扩写不读取助手发言作为事实依据，这很谨慎。但指代解析与事实授权可以分层，未来可让助手发言仅作为对话主题线索，不能直接当用户事实。

## 建议的验收顺序

1. 将 F1—F4 加入真实模块和服务回归，修复后重新跑全量离线测试。
2. 修 F5 的配置与恢复指纹，给真实运行生成完整 manifest。
3. 用现有42轮 product-life 跑一次受控预演，证明配置、接口和证据导出正常；不据此声明全部达标。
4. 执行附件的120轮主轨迹与隔离压力/生活/立场分支，分别报告机制、检索、原始模型、应用最终输出和人工体验结果。
