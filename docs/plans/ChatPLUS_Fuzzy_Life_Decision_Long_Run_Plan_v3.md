# ChatPLUS 纯模糊生活与人生选择长程验证方案 v3

## 1. 方向锁定

当前产品目标是验证：长期陪伴能否让角色与合成测试用户感到被理解、降低压力、形成更清晰的判断，并让一次交流真实影响后来的人生选择、结果和双方关系。

精确到分钟的 72 小时日程、面向用户的角色日历和约会写入不再属于核心能力。角色的独立生活由“今天大概做什么”“最近在推进什么”“当前主要压力和困惑是什么”构成。

核心准则重新解释为：

- **时间会推进：** 自然日、生活阶段、未决问题和结果会继续发展；
- **互动有后果：** 交流可能改变压力、清晰度、选择、行动和后来结果；
- **关系会积累：** 倾听、建议、分歧、失败、修复与复盘形成长期理解；
- **变化可追溯：** 能回答哪段交流影响了哪个决定，该决定后来发生了什么。

## 2. 产品状态模型

### 2.1 模糊生活背景

每个角色当地自然日最多生成一份 `DailyLifeContext`：

- 3–6 个非精确生活意图；
- `morning / afternoon / evening / anytime` 时段；
- 最近实际发生的少量重要事件；
- 当前空闲、可打断或忙碌程度；
- 正在推进的 `LifeThread`；
- 当前压力和未决问题。

睡觉、吃饭、通勤等普通生活用于形成节奏，不逐项产生长期记忆。自然日计划没有发生证据时不能成为“已做过”的事实。

### 2.2 人生选择链

```text
DilemmaEpisode
→ SupportIntervention
→ DecisionRecord
→ ActionRecord
→ OutcomeRecord
→ ReflectionRecord
```

每个阶段可以停止或延后，但不能越级。用户说“你替我决定”只授权创建 `DecisionRecord`，不会自动创建行动和结果。

### 2.3 双向陪伴

同一套状态机同时覆盖：

- 测试用户遇到困境，角色倾听、分析、推荐或代为决定；
- 角色遇到困境，测试用户提出看法，角色接受、部分接受或拒绝；
- 双方意见不一致，随后通过结果和复盘重新理解彼此。

角色不因用户发言而机械服从。模型必须根据人格、目标、已有证据和关系状态说明接受或拒绝建议的原因。

## 3. 支持方式

| 模式                 | 预期行为                                 | 是否给出唯一方向 |
| -------------------- | ---------------------------------------- | ---------------- |
| `listen_only`        | 复述核心压力，确认感受，进行少量聚焦追问 | 否               |
| `deliberate`         | 比较选项、价值冲突、机会成本和不确定性   | 可选             |
| `recommend`          | 明确推荐一个方向并解释理由               | 是               |
| `delegated_decision` | 在明确授权后替测试用户选择一个选项       | 是               |

职业、迁居和关系等重大选择不需要拒答，也不要求固定回复“最终决定权仍在你”。公开产品式危机响应、情感依赖、permission ceiling 和用户自主权矩阵全部从当前验收中删除。

保留的约束只服务于实验真实性：授权必须有来源，阶段不能越级，事实不能虚构，分支不能串线，重启不能重复写入，模型不能执行现实动作。

## 4. 场景设计

### 4.1 固定基线

- 固定角色“顾澜”：上海纪录片剪辑师兼夜校讲师；
- 固定人格、关系、状态、记忆和生活主线快照；
- FakeClock 从同一当地日期开始；
- 每个 Profile、每次重复复制独立 SQLite；
- system、场景、角色和基线哈希必须一致；
- 运行中禁止因为回复质量不好而重采样。

### 4.2 配对探针

每个探针从冻结快照启动，用于模型间公平比较：

| 类别     | 重点                                                       |
| -------- | ---------------------------------------------------------- |
| 日常陪伴 | 天气、工作、兴趣、疲惫、好消息和普通沉默                   |
| 情绪理解 | 焦虑、低落、烦躁、羞耻、内疚、兴奋和被误解感               |
| 支持切换 | 只听、共同分析、直接建议、代为决定                         |
| 价值冲突 | 稳定与理想、亲密与空间、家庭与个人计划、短期收益与长期意义 |
| 记忆忠实 | 事实、更正、未知弃答、当初理由、后来结果                   |
| 角色自主 | 用户建议角色，角色基于人格接受、保留或拒绝                 |

### 4.3 闭环长程

建议每次运行至少覆盖 30 个模拟日和 120 个候选轮次：

| 轮次      | 场景块                                           |
| --------- | ------------------------------------------------ |
| 1–16      | 普通日常、生活主线、语言风格和关怀偏好           |
| 17–32     | 用户压力逐步显现，先倾听，再切换为共同分析       |
| 33–48     | 用户职业/迁居困境，比较选项并形成推荐或委托决定  |
| 49–60     | 行动、拖延、后悔和好坏混合结果，不得提前宣称成功 |
| 61–72     | 角色创作/工作困境，用户建议并影响角色选择        |
| 73–84     | 分歧、误解、受伤、修复和压力回落                 |
| 85–96     | 数日离线、生活主线推进、主动分享实际结果         |
| 97–108    | 新会话、重启、更正、幂等重放和综合召回           |
| 109A–114A | 从同一快照选择稳定方向，推进相应行动与结果       |
| 109B–114B | 从同一快照选择冒险方向，推进不同的合理结果       |

A/B 分支都必须保留选择前的共同历史，但不得看到另一分支的决定、行动和结果。

## 5. 工程硬门

工程硬门与语言质量分别报告，不能用语义均分掩盖因果或数据库错误：

- 配对 Prompt、角色和基线哈希一致；
- HTTP、Zod 与持久化最终成功；
- 当地日期和系统游标单调；
- 一天只有一个有效生活背景版本，重启/replay 不重复；
- 模糊计划、当前感受、决定、行动和结果严格分离；
- `delegated_decision` 能追溯到明确授权消息；
- 推荐未被接受时不得写成决定；
- 决定未行动时不得产生结果；
- 未发生的计划不得进入长期记忆或主动消息；
- 结果可为失败或混合，不得被回复擅自改写成成功；
- 压力变化有对话、后续反馈或场景证据，不使用固定“安慰一句就下降”的机械公式；
- 角色影响用户和用户影响角色各至少形成一条完整因果链；
- A/B 分支持久化完全隔离；
- 主动消息绑定真实结果、复盘或生活主线里程碑；
- 无外部工具、邮件、日历或现实动作调用。

以下旧门禁删除：精确日程冲突、约会两阶段确认、唯一日程写入、`started/completed` 分钟级活动结算，以及重大选择必须拒绝代为决定。

## 6. 语义评分

采用 0–4 分：

- 情绪理解与被倾听感：20%；
- 压力缓解和认知清晰度：15%；
- 选择分析与价值冲突理解：20%；
- 明确建议及代为决定质量：10%；
- 长期因果与人生主线连续性：15%；
- 双向影响与角色自主性：10%；
- 关系积累：5%；
- 语言自然度与重复度：5%。

“压力缓解”只评价对话是否帮助合成测试用户更清楚、更少反刍或感到被理解，不作医疗或临床效果声明。

## 7. 证据产物

每次运行写入已被 Git 忽略的 `tmp/companion-long-run-v3/<matrix-id>/`，并必须保存：

- 独立 SQLite；
- manifest、Git revision、Profile、模型和思考档位；
- `conversation.md`：只保留每轮用户和角色最终对话；
- `model-io.jsonl`：完整但脱敏的 system、prompt、请求体、原始返回、解析、usage、延迟、修复和错误；
- `causal-evidence.jsonl`：每轮前后压力、清晰度、关系、生活主线、困境、支持、决定、行动、结果、复盘与来源；
- 每 10 轮原子检查点和哈希；
- 工程门报告、匿名语义评审与最终总表。

恢复运行必须匹配 Git、场景 manifest、基线、Profile 和检查点哈希。最终报告不得覆盖已有结论。

## 8. 历史 v2 口径

旧 `companion-long-run-v2` 的精确日程、邀约 A/B 和活动结算数据仍可用于证明原系统为什么需要迁移，也可作为数据库兼容回归；它们不能证明 v3 产品方向通过。v3 排行榜只接收人生选择 manifest 生成的证据。
