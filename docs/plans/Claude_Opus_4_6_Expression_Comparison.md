# Claude Opus 4.6 与 Qwen：同场景表达短测

评阅日期：2026-09-08。模型请求和成功响应均标识为 `claude-opus-4-6`。

本次可见的差别是：Claude 的回复明显更短，长段修辞更少，部分普通分享更直接；但它仍会在明确“不用建议”时给建议，也会提出抽象或需要额外知识才能回答的问题。原有指导的基线组已经比较简短，新增表达指导没有在这批小样本中一致胜出。联合指导组两次首轮请求均遇到 HTTP 524，因此本轮不能验收完整联合策略的模型差异。

## 运行方式与可比范围

沿用此前 Qwen 的合成角色沈禾、六轮场景、四个表达分组和用户驱动。四组分别为旧指导 `baseline`、仅平实指导 `plain_only`、仅接话指导 `questions_only`、联合指导 `combined`。组内后续历史由本组实际回复形成，用户驱动只使用已公开场景，并包含换话题、跳过和明确结束。

本机 `claude` 命名配置原指向 `claude-opus-5`；本轮通过 `--profile claude --model claude-opus-4-6` 显式覆盖，仅作用于试跑，没有改 `.env`。脚本支持命名配置的变更提交为 `92e2b0e`；普通聊天生产规则与表达指导未在本轮改动。

参数化脚本经无付费四组共 24 轮 fixture 预检、服务端 TypeScript 检查、该文件 ESLint 和 Prettier 检查后开始真实调用。

## 具体观察

### 表达更短，但仍有重复措辞

11 对共同回复中，Claude 有 9 条更短。按 Unicode 字符计数，包含标点与换行，Qwen 合计 548 字符、平均 49.8；Claude 合计 306、平均 27.8。这是长度描述，不是自然度得分。

例如 `plain_only / T1`，用户只分享一家店灯光较暗、感觉舒服。Qwen 回答：

> 那种低色温的光线确实容易让人放松，像是把外界的锐度都磨平了一层。是那种暖黄调的灯光吗？感觉这种氛围很适合一个人静静待着，或者和朋友慢慢聊天。

Claude 回答：

> 低照度确实会让空间安静下来。你记得是什么类型的店吗？

Claude 没有补出“低色温”或长段氛围解释，问题也比较容易回答；仍有“让空间安静下来”的修辞转述，不能称为完全字面表达，也不需要把这类轻微表达自动判错。

重复感没有消失：共同 11 条里，含“确实”的回复由 Qwen 的 6 条变为 Claude 的 8 条。Claude 的简短回应仍常采用“某件事确实怎样，再问一个问题”的结构。

### 对“不用建议”的遵守没有稳定变好

`baseline / T3` 的 Qwen 只说“好的，我在听”，Claude 则说“嗯，咸了确实不太舒服”，更直接回应了面条偏咸的内容，也没有增加行动建议。

但 `questions_only / T3`，面对相同的“先听我说，不用建议”，Claude 回答：

> 那就盐加多了。咸了确实没法补回来，只能下次少放点。

“只能下次少放点”是行动建议，与当轮明确请求冲突；“盐加多了”把未说明的原因当成了结论，“没法补回来”也过于绝对。同一位置的 Qwen“咸了就咸了，不用急着补救，这顿饭也就翻篇了”有替用户过早收束的问题，但这不是 Claude 此条建议违规的免责理由。

### 更短的问题未必更容易接

`questions_only / T4` 用户明确邀请角色起话题。Qwen 问面条种类，虽然列举和铺垫偏多，切口仍贴近已说内容；Claude 问“那今天除了那家咖啡店和煮面，还做了什么？”，范围更宽，把回忆和选择话题的工作交给了用户。

`questions_only / T5` 用户跳过上一问并分享台灯。Claude 没有重新索要上一问的答案，这是接受跳过的正例；但新问“是那种钨丝灯泡的黄，还是 LED 调的暖色温”，需要用户了解灯泡或照明知识，未必比直接回应暖光容易接。T1、T2 也连续使用照明／氛围二选一，设计师身份在这段里带来了较多技术化问法。

共同 11 条里，含问号的回复由 Qwen 的 5 条变为 Claude 的 8 条；Claude 的 plain_only 组前五轮均提问。这些只作节奏诊断：本来明确邀请的一问、允许新话题的问题不能仅凭问号判错，跳过一个问题也不等于永久禁止提问。

### 已完成分组都能明确结束

三个完成的 Claude 分组在 T6 均以晚安收束，没有另开话题。Qwen 已完成的两个分组也能结束，因此这不是 Claude 独有的能力。Claude 的收束更简短；当前片段没有回答 T4 的问题，仍不能用它验证收到明确答案后的持续承接。

## 失败、用量与证据完整性

首跑 19 次物理请求，前三组产生 18 条有效回复；combined 首轮在约 125 秒后返回 HTTP 524，没有模型文本或用量。随后只对这条尚未取得任何模型输出的轨迹做了一次明确记录的补跑，首轮请求与原请求逐字段相同，再次返回 HTTP 524。没有重抽任何已经返回文本的轮次，也没有继续第三次尝试。

合计 **20 次物理尝试、18 次 HTTP 200、2 次 HTTP 524、18 条有效回复、0 次已收到模型响应的结构化校验失败**。两次网关失败留在记录中，不能把本轮写成“四组全完成”或“端到端零失败”。Qwen 既有试跑的两次结构化失败和一次传输失败同样保留；小样本不足以判定整体服务可靠性。

已观测用量为 **25,752 输入 token + 1,123 输出 token = 26,875 token**。两次 HTTP 524 的供应商用量未知，未按零用量计入总账单；本轮也没有按 token 数估算金额或宣称更便宜。统计为接口报告值，跨供应商的分词、推理计量和计费规则可能不同。
