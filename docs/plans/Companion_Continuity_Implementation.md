# 长期角色陪伴：实施记录

基线：`dc51b5cba3dee574c86ba4bd58337c93b2d8b555`，2026-09-06。分支：`codex/companion-continuity`。

本轮依据《ChatPLUS_Development_Implementation_Guide.md》和“审视角色对话设计”三轮讨论实施。参考材料描述的是建议；下列边界是核查代码后采用的实现决策。原计划书保留原文，实施结果和偏差在本文件更新。

## 验收目标

普通相处能形成连续性：完整而有来源的记忆、可纠正的理解、无需强制建议的日常聊天、没有预设人生主线也能运行的角色，以及有证据且只影响适用范围的相处方式变化。保留明确委托决定、不可变已发布档案、角色队列、短事务、事件因果链和历史回放。

## 耦合分析与实现顺序

## 实施约束

- 独立模块并行开发，共享编排和Git操作统一完成；每批只暂存本批文件，验证后提交并立即推送。
- 追加数据库迁移，在隔离数据库和既有备份/恢复测试中验证；不对日常数据库执行实验或迁移。
- 沿用现有Fixture与provider stub，不发起付费模型调用。工程验证与真实语言体验验收分别报告。
- 新体验策略支持逐步启用；已证实错误的记忆不能随体验开关关闭而重新生效。

## 进度与验证

初始工作区只有用户提供的未跟踪计划书，没有既有源码修改；基线与远端 main 一致。开发采用独立分支、小批次暂存、验证、提交、立即推送的顺序。原计划书未被改写。

### 已采用的实现

1. **统一证据边界。** 原始陈述中的否定、条件、说话人、临时状态和计划／事实区别均保留。服务端能证明的有限事实使用确定性提取；无法证明的模型概括降为完整发言的归属报告，不能仅凭关键词重合写成事实。长证据整条保留或整条省略，当前用户消息不会在尾部否定之前被截断。
2. **当前投影和历史分离。** `MemoryValidityRepository` 是记忆、自传、事件卡和人格共同依赖的来源边界，各服务不互相调用以维护对方的内部投影。来源 hash、记忆 revision 和依赖登记共同决定当前有效性。记忆变更及派生失效在原消息提交事务内完成；旧自传 JSON、原消息、检索运行和已到信快照仍保留。索引重建不能给已失效对象重新授予有效性。
3. **上下文先于检索。** `ConversationContextPlan` 只使用同角色、同会话近期用户完整原文；原始 query 继续决定事实和授权。明确分析与情绪性“为什么”分开。扩写、未决指代和策略版本记入检索审计；旧策略最多三条，新策略复杂回顾最多八条。
4. **记忆使用权限。** 理解背景、适用范围内的行为偏好和主动提及分别选取。权限随每条证据原子序列化；预算丢掉辅助诊断段也不能丢掉权限。开启策略后避免兼容段重复注入证据。最近提及去重只记录助手回复中可核对的完整引用，不把召回候选冒充已说出口的回忆；意译识别仍有限。
5. **目标可空、作者来源真实。** 新原创和导入显式采用 `companion_character_v2`，目标与矛盾均可为空；作者目标不会改写价值，模型推断不能冒充作者设定。目标初始进度为零，不生成日历里程碑。表单、编辑、发布、恢复和生活初始化贯通该策略。旧角色缺省使用旧策略，历史 fixture 按其编译策略验证。
6. **一轮一个有效人格快照。** 已发布 `CharacterSpec` 保持不可变。`EffectivePersonaSnapshot` 带基线版本、人格 revision、记忆 revision 和有限适应；生成、检查、修复共享同一对象。修复也保留本轮的角色相关性选择。提交前检查版本，变化时返回 `409 stale_effective_persona`，完整回滚；重复 clientMessageId 重放原结果。人格缓存键含 revision。
7. **有限局部学习。** 自动学习只支持 `advice_timing / listen_first` 和 `follow_up_questions / fewer_questions`，由明确、持续的用户请求触发。每条适应同时依赖有效持久记忆和原始用户消息。普通聊天、引述、假设、一次情绪、助手自述不能作为学习依据。支持显式反向请求、撤回、来源纠正和作者改版后的兼容重基／重验；当轮生成使用旧 revision，新习惯从后续回合生效。行为提示只序列化 facet、practice、scope 与 ID，原文留在审计。
8. **书信历史隔离。** 新到信快照可包含到信时的有效人格；延迟处理使用历史角色版本和人格 revision。独立保存首次证据失效时间，避免没有下一轮聊天时仍使用已撤回解释。未来撤回不改变过去到信快照；重开数据库和重试保留同一 hash。旧快照不要求新增字段。
9. **相关的角色生活。** 普通分享和无关支持不常驻目标、矛盾或角色生活信息，价值仍独立保留。生成使用有界相关生活片段，因果检查保留完整快照。新目标线程由关联生活事件记录更新近期状态，单日“完成”不等于整个人生目标完成；旧角色的日历策略继续可回放。

生活主线的最后一轮审查补齐两个边界：用户的明确暂停／恢复请求还需本轮角色回复明确接受同一目标、同一操作，才能改变计划状态；两条完整消息共同记录来源，拒绝、条件或泛泛回应均不生效，计划调整不代表实际行动。自然暂缓后也可由已发生投入的合法证据恢复，助手自述须依赖已有行动验证链。作者复用目标 ID 修改标题／描述时建立独立绑定，旧线程保留终态历史，迟到的旧每日意图不会更新新目标；无关档案编辑不会重复创建同一主线。

### 配置、迁移和回退

- `COMPANION_CONTEXT_MODE` 与 `PERSONA_RUNTIME_MODE` 各支持 `off / shadow / enforced`，默认 `off`。`shadow` 记录诊断或观察，不应用新提示行为，也不写人格适应记忆；`enforced` 应用对应体验策略。两项可独立配置，完整体验建议一起开启。
- 原始证据真实性、完整证据预算、已纠正记忆的失效是基础正确性修复，不会因关闭体验策略而回退。
- 所有模式在提交前检查本轮冻结的记忆 revision。`off / shadow` 的来源变动返回 `409 stale_memory_sources`；`enforced` 的有效人格栅栏同时覆盖作者版本、人格 revision 和记忆 revision。`shadow` 若仅遇到作者并发改版，会跳过失配的观察，不影响正常聊天提交。
- 新增 `022_retrieval_context_budget.sql`、`023_memory_derivation_validity.sql`、`024_persona_runtime.sql`。旧未验证的派生自传／事件卡标记待复核，保留原文历史；不自动把旧模型概括提升成新验证事实。启动迁移前沿用项目既有备份流程，本轮未迁移日常数据库。
- 当前检索和自传读取按本轮时间排除过期依赖；人格撤回的源记忆还可作为原始历史保存，但通过本轮通用排除集合阻止其经自传、事件卡和基本记忆重新进入当前提示。
- 原始消息保持不可原地编辑的生产约束。若直接修改数据库中的旧消息，失效时间采用旧来源的保守归因；这类篡改不是提供给用户的历史编辑功能。
