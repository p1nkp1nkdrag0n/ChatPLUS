## 附件与评分隔离

原始四份文件保持原文。运行器按字节核对两个 JSON，当前 SHA-256 为：

- `03_scenario.public.json`：`0b3ca233b58242273c619c1013938b2aa0d1b13ddd937888de993586cffcc585`
- `04_oracle.private.json`：`83c30681d5c1c159aa93022aaad1651437ed4bd9e793682988d1f21c713224c4`

公开场景的当前 `userText` 进入产品消息 API。角色模型看不到未来步骤、`kind`、驱动操作、事实账本及评分要求。评分文件仅复制到隔离运行目录，由离线审计器生成逐探针工作表。

运行产物包含请求与原始响应、逻辑模型调用、最终用户可见回复、检索诊断、人格 metadata、实际对话整理 checkpoint、书信回执、SQLite 一致性备份及预算账本。`review-worksheet.json` 为自动生成工作表；完成后首次创建 `review.json`，人工评分填写后不被恢复运行覆盖。原始模型、应用最终结果、真人体验分别待评，不自动将关键词命中写成语义通过。

## 新增的可执行入口

无费用预演，默认使用附件的前 16 轮：

```powershell
pnpm test:continuity:fixture cc-fixture-unique --turns 16
```

完整固定输入预演：

```powershell
pnpm test:continuity:fixture cc-fixture-full-unique --turns 120
```

该入口使用真正的本地 TCP HTTP 路由，书信复用现有产品 helper。D14／第 64 轮后退出 worker，由父进程启动新的 worker，保留同一实例密钥、SQLite 和冻结配置，在 D18 继续。进程 PID 的实际变化单独记录。进程锁排除同一 run 的并行执行；恢复时核对已完成回合与数据库、固定消息 ID、原文及回执。

角色通过正常生成、发布流程产生；无目标角色如被生成了目标或矛盾，会保留失败草稿并停止，脚本不偷偷删除后继续。发布后的零对话基线另存为 `baseline.sqlite`，支持 `--baseline <旧运行目录>`。A0/A2 正式对照应从同一份经过 hash 校验、没有聊天污染的基线复制；不能分别随机生成角色再声称严格配对。

组别由 `--group A0|A1|A2` 决定，分别为 off/off、enforced/off、enforced/enforced。主轨迹使用配置中实际 retention，并写入 manifest。独立压缩压力段需要另开运行与参数，不将恢复用 SQLite 备份计为记忆整理。

## 下一步拟请求的真实 API 授权

先授权一个小规模 A2 预演：使用本地 `bigmodel` 命名档案，固定前 16 轮，不调用用户模拟器或付费 judge。上限为 **50 次实际模型请求**，另设 **2,000,000 预留单位**的准入上限。单位按“实际请求 JSON 的 UTF-8 字节数 + 输出 token 上限”预留，含重试和修复；它是保守的工作量限制，不是供应商的精确 token 账单或人民币费用上限。

每次外部请求之前先将预留写入账本。超时和进程中断的调用仍占预算；缺少 usage 记为未知。越预算、配置不一致、恢复证据不一致或生成基线不合格即停止；不为语言质量反复重采样。

只有在用户授权后才执行以下命令，执行结束或失败均清除本次授权环境变量：

```powershell
$env:RUN_PAID_CONTINUITY = '1'
try {
  pnpm test:continuity cc-live-pilot-unique --profile bigmodel --group A2 --turns 16 --requests 50 --token-units 2000000
} finally {
  Remove-Item Env:RUN_PAID_CONTINUITY
}
```

已有命名档案的凭据不进入命令参数或报告；日常数据库和 `.env` 不被改动。根据首批真实输入规模、调用次数和 usage，再提出完整 A0/A2 两条 120 轮轨迹的预算，不将首次小预演授权自动扩大为全部矩阵。
