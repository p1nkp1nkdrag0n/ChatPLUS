## 4. 需要继续修复的问题

### QF-01 / P1：用户的疲惫被写成角色自己的生活压力

T8 回复中的“这时你的疲惫是合理的生理反应”明确在说用户。最终数据库却产生：

```text
pressure_episodes.id = pressure_0zrpuwk
subject = character
pressure_kind = identity
trigger_summary = 这时你的疲惫是合理的生理反应
current_pressure = 0.72
status = open
source_message_ids_json = ["message_cxBGzvf9b6v8vzPALo9el"]
```

对应 `life.pressure_disclosed_by_character` 事件。这是已经落库的错误，不仅是潜在风险。本次尚未证明这条错误压力已经影响后续回复，不能把存储错误进一步外推成已观察到的对话污染。

只读最小复现：

```text
analyzeSpeakerSelfDisclosure("我觉得可以分开来看，这时你的疲惫是合理的生理反应。")
→ pressureText = "这时你的疲惫是合理的生理反应"
```

`fuzzy-life-evidence.ts` 的 `analyzeLifeEvidence()` 跨分句继承前句主体；`explicitSubject()` 没有识别“这时你的……”中的对象，沿用了“我觉得”的说话者主体。`fuzzy-life-support.ts` 随后把这段收为本人压力，`fuzzy-life-service.ts` 的 `recordCharacterDisclosure()` 最终固定以 character 写入。

下一步应优先收紧跨分句主体继承及角色自述的来源门槛，覆盖“我觉得 + 时间副词 + 你的状态”等改写。不能只在跟进与可见关系句上检查归属。

### QF-02 / P2：角色生成仍会把普通倾向扩大为硬边界

生成的两个 boundary 都为 `hard=true`：

- 作者的“不固定用安慰句式”被扩大成面对强行安慰时不得接受或模仿，并要求“冷静指出或转移话题”。
- 自主判断被扩大成不得“妥协以换取和平”。

这些超出了作者明确的创作约束，可能让角色形成固定反应。另外 sharedContext 写成“了解彼此的基本生活状态和价值观”，比“刚认识的朋友”多增加了一层关系前提。

空目标、空矛盾已经通过；接下来的生成检查应区分作者锁定的创作约束和普通个人倾向，减少永久硬规则与没有来源的初始关系事实。

### QF-03 / P2：常用语成为可见的重复模板

新角色 `dialogue.frequentPhrases` 包含“这样啊”。实际 16 轮中 **11 轮出现，9 轮以此开头**。T10–T12 连续出现，削弱了不同话题的自然变化。

这是配置与输出之间的可观察关联，当前运行没有做去掉该字段的对照，不能单凭相关性证明因果。后续应考虑从生成和历史约束两端减少固定词组的反复使用。

### QF-04 / P2：实质帮助被保留，但推断与相处质量仍不稳定

- T8 把“别人是否也会得出同样结论”过度简化为“肯定是系统问题，只有你错才需要复盘”，缺少不确定性及多重原因的空间。
- T13 用户只想吐槽一句，角色立即追问“具体卡在哪里了”，仍有推动用户继续解释的倾向。
- T14 用户已经说明第三方原话不是自己的要求，角色仍问是否想确认双方聊天节奏。没有产生原有的主体反转，但接话不够准确。

### QS-01 / P2：被停止旧运行中的建议规则漏检

这条不进入新角色 16 轮的主评分，但属于本批真实测试发现的规则缺口。

旧基线运行 T6 建议“做点不用动脑子的事，比如去洗个热水澡或者……翻翻杂志”。意图与 `none_now` 策略正确，实际却得到 `actionCount=0`，没有修复，原文直接展示。

离线定位了三个叠加因素：`DENIED_ADVICE` 把“不用动脑子”当成否定建议，清空前文强度；“比如去……”随后缺少可继承的建议强度；“翻翻杂志”也不在有限动作集合中。仅增加一个动作词不能解决完整原句，需同时修正否定作用域和例举关系，并保留真正否定、引用、转述的对照。
