## 1. 修复的实际行为

### T14：请求的方向与历史履行分开

- 新增 `InteractionEvidenceSnapshot`，明确请求者、预期行为主体、接受者、话题范围、来源消息及事实层级。请求、意愿、承诺、一次行为与反复行为分别表示。
- 用户要求角色先倾听，不能变成“用户以前一直先听角色说”；即使主体方向正确，也不能把一次请求直接升级为“角色这些年一直做到”。缺少证据表示不能支持该断言，并不表示已经证明事情从未发生。
- 历史证据独立于当前生效的相处习惯：工作话题的请求可以解释历史归属，但不会因被检索出来而自动在其他话题生效。用户撤回、被替代、待复核或来源失效的习惯，不会经新证据入口重新带回。
- 生成与修复共用来源视图，仅传递锚点对应的完整原文；原文是归属证据，不是新增的当前相处指令。
- 旧错误 assistant 消息仍保留在原始数据库和审计中。下一轮模型历史视图、checkpoint 输入与派生证据会排除被判定不受支持的完整句子，并保留正确部分及排除说明。引用、否定、假设和第三方转述保留完整语境后再检查。

涉及：`packages/contracts/src/interaction-evidence.ts`、`packages/features/src/interaction-attribution.ts`、`apps/server/src/services/interaction-history-service.ts`、`checkpoint-service.ts`。

### T8：有引用不等于有跟进依据

- `normalizeFollowUpCandidate()` 和公开的 `FollowUpService.createFollowUp()` 共用来源判定。分析请求、感谢、理解、单纯引用、预测和含糊采纳不能被转成用户计划。
- 仅接受来源明确支持的用户事件、具体计划、主动跟进请求，或有相应主体依据的承诺。条件或不确定计划采取保守拒绝策略。
- 服务端舍弃模型的预期结果文字，从真实事项重新生成“询问是否发生、是否尝试或安排有无变化”的指导；不预设用户已采纳、执行或成功。
- 缺失证据时不再自动补用户原文。共享承诺的另一方证据来自实际同角色、同会话的相邻消息；角色承诺以最终已存储回复为准。
- 来源绑定原文 SHA256、角色、会话和时间。创建、重验、领取与发送资格共用既有 `MemoryValidityRepository` 的有效性边界。原文未变但相关记忆已失效，同样不能继续使用。
- Care cue 的指导由用户来源重建，避免模型虚构的活动混入后续关心。

迁移 `025_continuity_grounding.sql` 为 follow-up 和 care cue 增加可空的 `grounding_json`。未验证的旧行保持原生命周期状态，但不再有领取或发送资格；不会伪造成“用户取消”。`revalidateFollowUp({ agentId, id, timezone })` 可逐条重验未发送、未尝试的 pending 跟进。合法旧事件可恢复；T8 类型的旧错误保持隔离。相对日期按原始时间解释，重验不会把旧“明天”重新推迟到现在的明天。旧 care cue 本轮没有批量自动恢复路径。

涉及：`packages/features/src/follow-up-grounding.ts`、`follow-up.ts`、服务端 `conversation-continuity-service.ts`、`follow-up-service.ts`、`follow-up-repository.ts`、`proactive-generation-repository.ts`。

### T6：普通交流中的建议负担

- 从当前请求确定 `requested`、`none_now`、`optional_light`。明确求助保留具体帮助；倾诉和要求先说完时暂不安排用户行动；普通分享最多允许一项轻量、可选建议。
- 按实际建议表达识别行动负担，而不是按段落数或行动关键词简单计数。原始 T6 回复中的画画、列清单、洗澡、出门走路识别为四项行动。
- T8、T15、T16 的明确分析或建议请求作为正向控制保留；本轮明确请求不会永久撤回原有相处习惯。
- `reply.text`、每个消息块及全部消息块合并后的行动负担均被检查；不允许通过分散气泡规避总量限制。

涉及：`packages/features/src/advice-policy.ts`、`conversation-context-plan.ts`、`prompt-assembler.ts`。

## 2. 耦合边界与最终提交

一个聊天回合共享同一组冻结证据、当前请求和一次模型修复额度。原始生成、世界效果准备、事实/同意呈现之后仍有最终检查；纯检查可以重复，模型修复不会因此无限重复。修复失败时删除不受支持的完整句子并重建可见消息块，不做机械代词替换。

已经由确定性合同核准的显式事实及第三方同意呈现，不会再交给最后一个语义修复模型改写。原有因果检查仍参与最终模型修复结果的检查。

回复文字修好之后，错误互动记忆候选继续接受筛选；跟进及 care cue 在正常提交阶段按真实消息重新建立依据。独立用户事实保留：HTTP 回归同时验证了错误关系记忆被拒绝、用户明确的面试记忆和面试跟进仍写入。重放相同 `clientMessageId` 不增加消息、记忆、跟进、人格适应或修复调用。

审计新增原始/最终回复 hash、问题片段、来源 ID、修复次数及最终建议负担。provider 原始模型记录继续保留；修复成功不被报告为模型原始输出从未出错。

**范围限制：** 这些检查是有明确覆盖范围的规则，不是通用语义蕴含模型。复杂或隐含计划可能被拒绝，未覆盖的互动表达仍需真实回归和独立评分。数值型 `stateDelta` / `relationshipDelta` 没有新增逐字段来源合同，仍使用原有世界效果/关系门槛；本轮没有声称对所有世界副作用做了完整自然语言因果证明，也没有将同轮所有状态一律清空。既有整条用户消息的记忆门槛，对“第三方转述与独立事实混在一条消息”仍可能保守拒绝模型记忆，该行为不在本轮改写范围。
