## A：确定性缺陷

- 作者特质不再以通用 trait ID 关联另一语义的模型描述。只有唯一、规范化后相同的名称可安全匹配；无法匹配时保留作者原句，保留模型候选的推断来源，处理 ID 碰撞。
- 物品位置抽取区分“还在用／办理”和“还在抽屉里”，不把“也”当物品。迁移 `027_stored_item_extraction_repair.sql` 仅隔离已确认不可能的旧物品键，复用有效性触发器撤销派生当前内容并推进 revision；同条原文中的正确事实保留。
- 书信每次调用生成独立的不透明局部引用表，精确、唯一映射到允许的持久来源。称呼、署名由服务器快照决定，正文显式的身份／收件方向冲突会拒绝；执行和加密前再次校验。该有限检查不宣称能识别任意隐含叙述视角。

## B：事实修订、当前值与历史

有限投影覆盖同事／妹妹等主体姓名、通用或受支持项目标签的编号、常用饮品。规范事实与原始来源绑定，校验用户、角色、来源消息、时间和完整原文；引用、错误归属、否定及问句中的未确认前提不获得事实权威。任意中文项目别名或复杂所有权句式未被安全支持时，不强行投影。

普通纠正只需要足够明确的对象和正确值，不要求 `correctionReason`。真实时间变化标注 `temporal_update`，错误更正标注 `explicit_correction`；提交替换、旧派生失效和 revision 更新走既有事务。原文和历史保留。

事实查询需求与表达风格并行规划。“同事叫什么，项目编号是什么”会分别为请求的主体／属性保留经过来源验证的候选，再使用全局 top-k。对旧版无 claim 的复合原文建立只读的有限事实视图，沿用原来源。裸句“你记错了”只在同会话有一个明确的前问对象时继承查询对象，存在歧义则不擅自选取。

普通当前值提示只给当前正确内容和出处，避免旧值、旧 quote 或纠错原因再次进入生成；部分事实已取回时先回答已知部分，缺项表述为本次未取回。当前事实查询与历史查询分开：历史视图沿最多 32 条已验证的时间变化边读取，到错误更正即停止，不重新激活失效记录。例如咖啡→茶→水可回答最早咖啡；咖啡被纠正为茶→水则不能把错误咖啡当真实历史。

专项实际执行了 10 轮干扰、新会话、SQLite 关闭后重开、跨主体保护、三事实覆盖、旧原文兼容以及历史分支。重开用例在同一测试进程内重建数据库连接和服务，没有另外启动操作系统进程。压缩测试真实提交两个 checkpoint 和两个自传快照，检查旧派生失效、新压缩后同事与妹妹事实可用。这证明存储与读取路径，不代表真实模型在压缩中的语义质量已经验收。

## C：修复限于明确冲突

`advice_load_v3` 和 `conversation_semantic_boundaries_v2` 保留原始与最终诊断，并区分 `confirmed`、`uncertain` 和无问题。当前明确不要建议时的动作建议属于确认冲突；从倾诉推断的偏好和低影响风格问题默认只记录诊断。描述、名词化、完整引用与真正的动作建议分别测试，问号不能让动作建议绕过政策。

初始诊断在后续修复后仍可追溯。修复复用一个既有预算，无确认问题的保守路径不改写内容；没有额外的去修辞模型调用。重放保持零新增调用。词法规则仍有边界，不以动作词覆盖率代替语言理解质量。

真实试跑联合组的“喝口白水”反例另做离线回放：现有正式检查已判 `confirmed`，确定性兜底去掉建议句并保留内容问题；仅增加真实措辞及描述、已发生动作、引用、否定回归，没有为了该文本扩充生产规则。

## D：同一份表达视图与生成依据

沿用 `questionIntent` 的 `none`、`natural_optional`、`necessary_for_explicit_task`。明确结束、当前禁止优先于长期“主动问一点”；当前明确邀请可在本轮覆盖少追问；“以后”的偏好不取消“今晚”的收束。只说不要建议仍允许贴近内容的问题，纠正后的独立求助继续处理。

近期线索来自同会话、同角色的有界最终消息，最多六条，每条不超过 1,200 字符，超长消息整条省略。短答、跳过和未回答不会形成未答队列、长期偏好或关系扣分。

有限实践在既有合同内增加 `plain_expression` 与 `natural_questions`，复用来源、范围、版本、撤回和重启机制；未把主动接话塞进 `fewer_questions`。明确引用、自述、临时要求和短答有负控制。生成和修复使用同一表达视图，平实默认允许正常创作、幽默及按需类比。

修复的 `replyGrounding` 来自初稿最终预算实际保留的有效 JSON 片段，包括检索事实、参考上下文、近期原文和生活依据。整条记录裁剪后的有效 JSON 同样共享，已丢弃的片段不被修复恢复。HTTP 集成覆盖提问、接住回答、接受跳过、其他合法修复及幂等重放。

## E：纠错协议与真实试跑

`correction-first-protocol.ts` 提供可注入发送／评估步骤的自适应协议及汇总。只在实际观察到目标错误时发送 C1，仍错误才发送 C2；最多两轮，不为正确首答制造虚假纠正，不通过隐藏重抽获得通过。未知判定保留未知。

汇总分别保留首答机会、E0、R1、R2、恢复后的各阶段保持、同一错误的暴露次数与跨会话复发、连带破坏及用户纠正负担。保持分母只纳入实际发生的对应转换，没有重启或压缩就记 N/A。该协议已通过 11 项测试，尚未替代原长测评分器，也不是已完成真实模型全路径纠错实验的声明。

新增 `correction-expression-pilot.ts` 比较旧表达指导、仅平实指导、仅接话指导和联合指导，模型、角色及当前规划器相同。每组使用本组已有合法对话，支持 `--fixture`；真实调用必须显式设置运行开关。实际执行的边界与逐条离线评阅见[试跑评阅](Correction_Expression_Pilot_Review.md)和[可复核证据](Correction_Expression_Pilot_Evidence/README.md)。

本次 Qwen 试跑共有 20 次物理请求尝试，19 次 HTTP 响应，17 条有效回复；2 次结构化输出失败与 1 次 TLS 失败全部保留，没有重抽已失败分组。可观察 token 总数为 26,936；TLS 失败的供应商用量未知。旧指导组在 T5、仅平实组在 T2 结构失败，其他两组各完成六轮，因此不能把本批结果当等长对照实验或整体改进证明。

已完成片段包含具体起话题、接受跳过和明确结束的正例，也出现未提供的细节、抽象二选一、修辞惯性，以及联合组明确不求建议时仍给建议的反例。试跑只调用生成，没有经过正式聊天最终修复路径；不把这条输出直接当正式系统最终呈现结果。自然度验收仍未通过，真人连续交流未执行。未开始新一轮付费 120 轮长测。
