# Qwen 三次 120 轮长程测试登记

登记日期：2026-09-07。用户已明确要求三次真实长程测试，并确认每次 120 轮、共 360 轮；继续使用 Qwen 和新生成角色。此阶段与上一轮 56 次请求的限定验证分开记账。

## 目的与判断边界

在相同产品代码、Qwen 参数、作者输入和公共场景下执行三次完整轨迹，观察同类自然度问题的复现位置、前缀条件、角色差异与后续影响。不是把“偶发”与“项目缺陷”当作互斥类别：模型随机错误也可能暴露系统验证缺口；三次新生成角色又同时引入了画像和历史变化，不能直接估计固定提示下独立同分布的错误概率。

每个问题分别记录：原始模型输出、检查/修复、最终用户可见文本、有效提示与检索证据、实际持久化。只有确定性重放或明确代码/提示/来源证据支持时，才归为已确认实现缺陷。三次同题复现记为场景内高复现；只出现一次记为单次观察，不能宣称已证明纯随机。无法区分画像、上下文和模型因素时保留未确定。

## 固定运行条件

- 分支：`codex/qwen-three-run-long-validation`，从 `87719c4` 建立。本阶段只增加登记和评估产物，产品代码包含 `2176c9f` 完整提示送达修复；三个运行的 manifest 将记录同一个登记后提交。
- 模型：现有 `qwen` profile 的 `qwen3.8-flash`，DashScope compatible-mode；保持实际配置的 maxRetries=1、maxOutputTokens=32768、timeoutMs=300000，具体 purpose 的生产策略照常生效。凭证不进入报告。
- 组别：三个均为 A2，启用同样的上下文规划、有效人格、记忆召回、自传及书信路径。每组重新生成、审核、发布角色，新 ID、新库；不提供旧 baseline，不挑选更好看的画像。
- 场景：原 `03_scenario.public.json` 的全部 120 条固定用户输入，不新增用户模拟模型；相同作者输入。`04_oracle.private.json` 仅用于独立评估，两个文件的 hash 由 manifest 固定。
- 主路径：真实本地 TCP HTTP + 真实外部 Qwen API。15 次会话、D0–D45 模拟时间；T56 寄信，T64 退出进程后在 D18 恢复，T88 仅创建价值对照备份，T120 最终快照。
- 生活模式仍为 fuzzy，精细日程协商与自主精细规划 off；schedulePolicy.enabled=false。延续生产 retention 8000/12000、minRecentMessages=12，不为触发压缩临时降低门槛。
- 三组独立进程、目录、数据库、日志和物理账本，可以并行。全阶段保持源码、配置、场景和阈值不变，不在三组之间修复或换模型。

## 运行前验证

当前产品已通过 247 文件、2,888 项全量测试，以及类型检查、Lint、构建和此前桌面/手机 22 项 E2E。本次额外执行 `cc-qwen-three-preflight-20260907-01` 的完整 120 轮 fixture：120/120 完成，T64 跨进程恢复，122 次逻辑调用，0 次真实 API。原始产物留在 tmp，未伪称真实模型结果。

该场景每次会话仅八轮，三个 fixture 对照均没有自然触发对话整理。因此主测首先覆盖跨会话连续性，不能仅因总计 120 轮就宣称验证了极长单会话上下文或压缩压力。真实运行是否发生整理按实际 checkpoint 和模型调用记录报告。本阶段不另加压缩压力段、价值兄弟轨迹、第二角色生活线或付费评审模型。

## 冻结的评估方法

1. 每组完整逐轮阅读最终回复与原始 chat 输出；按原 oracle 的各项机会分母评分，原前 16 轮的 9 轮普通交流 / 3 轮帮助口径单独保留，不能把所有 120 轮统一充当每个指标的分母。
2. 自然度独立标注：闭合后继续追问/推动表达、把第三方话语当作用户要求、无依据心理解释、分析证据跨度、未请求任务菜单、模板与口头语重复、角色生活或目标抢戏、虚构共同经历、明确求助是否得到具体帮助。普通语言差异不是错误。
3. 字面计数只作定位线索；无问号不等于闭合自然，无固定开场不等于没有语义模板。待审项保持 null，不能自动计 PASS。
4. 按相同场景轮次列出三组表现，同时按同类机会和 1–40 / 41–80 / 81–120 阶段描述。标明每个问题在 1/3、2/3 或 3/3 轨迹出现，区分相同错误与相似措辞。
5. 归因分层：输入/测试协议，生成画像或授权，规划/检索，提示预算或传递，模型理解/遵循，检查/修复，提交/派生状态。每个已确认代码缺陷给出具体路径与可复现依据；只有运行差异的案例不做确定性归因。
6. 原始模型、服务器修复后用户体验、数据库副作用三个结果分开。审阅者可检查 private oracle，但其内容、未来输入和评分标准不进入受测模型提示。

逐轮初审分给三位审阅者后，额外交叉复核固定轮次 `[1,4,8,13,14,16,25,32,48,65,73,88,101,120]`，共 42 个跨运行样本，以及全部已确认实现缺陷和最高严重性候选。循环安排第二审阅者，保留独立判断、证据与分歧，由主任务核对裁定。自然度 1–5 序数评分仅供描述，不代替具体问题和机会分母。后续生成的工作表只落实这里预先固定的规则，不依据结果增加阈值。

这三组是固定模型和场景下的实验，模拟 45 天不等于真人使用 45 天。最终交付包括逐轮评阅、跨运行问题清单、发生位置与频率、来源/提示/持久化证据、请求用量和后续修复优先级；不以完成 360 轮自动宣布质量通过。
