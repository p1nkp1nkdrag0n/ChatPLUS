GitHub Actions [34020637848](https://github.com/p1nkp1nkdrag0n/ChatPLUS/actions/runs/34020637848) 在 `d0a8cd23bb502d87af673c7179c46275f72e96c3` 上完成后，Browser acceptance 和 Lint, types, tests, and build 通过，Deterministic long-run acceptance 失败。

## 根因与修改

1. **测试模型没有实际提供所要求的支持和选择。** shared-033、shared-046 和 shared-076 的泛化回应没有发生分析、推荐或角色决定。场景自有 fixture 现提供可验证的实际回应，并继续明确区分建议、接受、决定、行动和结果。冻结场景用户文本及工程断言保持原样。
2. **跨日推荐未能重新关联已知困境。** shared-046 的用户请求依赖之前已讨论的选项，但旧来源超出近期窗口；shared-048 的授权因此落到只有 A/B 占位标签的新困境。现在仅在同一会话中，实际推荐明确且唯一地命中已知选项时重接困境；后续委托仍需要用户的新授权。否定、引用、无关推荐和含糊指代不能建立这种关联。
3. **已完成的并列行动漏记。** “已经拒绝合同，并和伙伴确认启动项目”中的完成体和第一人称未正确传递到并列分句。现在保留精确原文与继承时态，同时单独判断各分句所属事项，避免把不同事项的行动混在一起。
4. **跨日结果与结构化观察丢失前置证据。** 明确说明几天后结果的文本可以依据已识别事项和可核验来源关联先前行动；一般指代继续使用短期窗口。已有结构化观察通过系统通知和领域事件的确切 agent、session、decision、action、outcome 及时间关联核验，不再将其第三人称摘要重新当作普通聊天解析。没有匹配来源的记录继续走原有证据规则。
5. **混合结果的后半段被截断。** 明确结果段落中分号后的同主体实际感受与紧邻的混合结果声明一并保留，使后续反思能够看到收益和代价；假设、未来行动及无关事件仍被排除。
6. **多个开放事项影响当前对话的续接。** 历史压力仍保持开放时，支持模式切换无法选择当前事项；新旧决定共享“收入”等普通词时，后续结果也可能歧义。续接使用当前对话内可核验的消息与干预、行动或结果来源，要求候选唯一，不依据最后更新时间猜测。

生产代码没有增加场景角色名、机构名、轮次 ID 或 `long_run` 特判；没有删除工程断言、降低门槛或将失败改为跳过。
