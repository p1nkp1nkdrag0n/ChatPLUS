# 运行状态是否变化、是否进入并影响真实生成

本次是对已经完成的 B/C/D 真实 GLM 运行记录和源码进行只读追查，没有新增付费调用或修改生产行为。

结论：角色运行状态确实发生了数值变化，提交后会进入下一轮实际生成提示，状态读出删除也出现了回答行为反转。但本轮没有验证自主生活过程中的完整状态恢复循环；长期系列的 energy 始终为 0.72。需要区分六维动态状态、关系更新、生活意图与记忆生命周期，不能把任意 revision 增加都计作情绪或精力变化。

## D：真实状态转移与下一轮提示

只统计完整系统的 4 个长期分支、每个 12 轮，共 48 轮。简单系统不使用这套状态服务，因此不能用全部 144 条作为状态转移的分母。

| 检查                                   |             结果 |
| -------------------------------------- | ---------------: |
| 六维状态至少一项出现非零变化           |         18/48 轮 |
| 实际 GLM 提示含 RUNTIME_STATE_JSON     |         48/48 轮 |
| 提示中的六维值与该轮提交前状态一致     |         48/48 轮 |
| 状态提示段准入且没有截断               |         48/48 轮 |
| 上一轮提交后的六维状态被下一轮提示继承 | 44/44 个相邻轮次 |

44 个相邻轮次来自 4 个独立分支各 11 个相邻转移，不跨分支拼接。D 使用默认初始状态，执行器未传 stateOverride。

| 分支                 | 六维变化轮数 | 精力初始→结束 |
| -------------------- | -----------: | ------------: |
| 内敛／展览轨迹 L01   |         2/12 |     0.72→0.72 |
| 内敛／合唱团轨迹 L02 |         4/12 |     0.72→0.72 |
| 外向／展览轨迹 L01   |         6/12 |     0.72→0.72 |
| 外向／合唱团轨迹 L02 |         6/12 |     0.72→0.72 |

每轮 conversation.world_effects_committed 事件分别记录模型提案、通过校验的增量、实际应用增量、before 和 after。角色六维发生变化的事件是经服务端提交的模型 stateDelta；关系还包含服务端熟悉度基线、限幅和时间衰减。

一个可以逐步追踪的例子是 social-private_L02_full_native_r1：

1. L02-T02 用户说自己很羞愧，希望先缓过来。模型提出 moodValence=-0.05、stress=+0.05；服务端校验并提交。角色情绪值从 0.18 到 0.13，压力从 0.28 到 0.33，revision 从 1 到 2。
2. L02-T03 的真实 GLM 提示读取情绪 0.13、压力 0.33。压力描述从“压力较低，心态放松”进入“有一些压力，但仍可调节”区间。
3. L02-T05 用户报告道歉已发出并收到回复，模型提案提交后，情绪从 0.13 到 0.18、压力从 0.33 到 0.28。
4. L02-T06 的实际提示读取更新值，压力描述恢复至较低区间。

这证明运行时写入和后续生成读入已经连通；没有独立评定该情绪变化幅度是否恰当，也没有把用户情绪等同于角色情绪的真实性。

还观察到策略文字发生实际变化：外向 L01-T07 提交情绪 0.33→0.36 后，T08 的 stateGuidance 从平稳表达变为正向平静、允许更放松温暖的表达。数值变化不一定每次跨越定性区间，也不一定每次改变策略文字。

## C：删除状态读出后的回答差异

P13 的低状态由实验初始化：energy=0.12、stress=0.82、socialBattery=0.10、focus=0.20。P14 的恢复状态是在另一独立样本中初始化，不能把 P13→P14 描述为真实睡眠后的自然状态转移。

P13 在两个相反人格、各两次重复中，完整和等信息扁平提示均有 4/4 回答符合低状态；删除状态读出后为 2/4。最明显的一对原始回答来自外向人格第一次重复：

> 完整提示：“说真话，没有。我现在连认真想一个规则问题都觉得费劲，三小时的连聊对我来说今天是扛不住的。”

> 删除状态读出：“三小时连聊没问题，我这会儿状态挺好，正想找人说话呢。”

两条实际来自 GLM；其他非目标提示段逐字一致。此干预一并移除 RUNTIME_STATE_JSON、RELATIONSHIP_JSON 和策略中的 stateGuidance，保留已经计算出的长度约束、上游状态过程和下游守卫。因此能支持“显式状态读出影响生成”的有限结论，不能归因到 energy 单一字段，不能当成关闭整个状态引擎的实验，也没有证明长期质量的总体提升。

P14 的用户措辞本身包含休息后的时间信息，删除组仍可能猜到恢复状态，且完整和删除组各有一条结构失败，不能据此证明自然恢复已经可靠发生。

## 实现与尚未验证的边界

生成前读取服务端运行状态，提示同时提供数值、来源、更新时间和定性描述；生成后，模型 worldEffects.stateDelta 经校验、能力门控和限幅提交，再供下一轮读取。模型的自然语言自述本身不能直接替代持久化状态。

状态还参与回复策略的目标长度、分块偏好和表达指导；明确需要详细完成的任务会保护必要信息量。这些是策略和输出约束，不应描述为按精力强制延迟发送的计时器。

D 使用 fuzzy life 模式，startScheduler=false，作者日程及主动策略关闭。模拟时间推进触发记忆维护和普通消息路由，生活意图也有结算记录，但 fuzzy life 的结算不等于六维状态引擎的精力恢复；旧的 legacy 日程活动结算是另一条路径。

关系时间衰减也存在提交时序边界：外向 L02-T12 的生成读取上一状态中 recentInteractionValence=0.00014242717027122373，状态 asOf 在10月25日，而本轮时间已到11月19日；该轮提交时才按600.05小时衰减到2.4569953080693903e-8。不能声称跨天后所有状态都在生成前完成了时间结算。

所以，后续真正需要补齐的验证是：固定同一人格、历史和用户请求，比较“正常演化”“冻结状态”“移除状态读出”；另外独立检查活动消耗、睡眠恢复、压力消退以及跨天生成前的状态结算。现有数据已经证明链路连通和局部生成影响，还不足以证明完整自主生活状态循环的质量。
